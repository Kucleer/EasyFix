# 把错题录入 EasyFix

家长贴来孩子批改过的作业或卷子照片，说"录入错题"。你看图，判断孩子哪几道做错了，
把错题作为**一份卷子**提交给 EasyFix。没问题的题直接入库，拿不准的标为"待核对"
留给家长看。

本文件讲怎么做、什么时候停下。字段的完整格式看同目录的 `payload-format.md`，用到时才读。
小工具每个命令的参数和退出码看 `python <技能目录>/easyfix_intake.py --help`。

**`<技能目录>` 指本文件所在的目录**，是 `~/.claude/skills/easyfix-intake/` 或
`~/.agents/skills/easyfix-intake/` 之一（本文件从哪个加载就用哪个），脚本和本文件在一起。

## 只走小工具（不可商量）

录题**只有一条路**：用 `python <技能目录>/easyfix_intake.py` 的四个命令提交，
由系统接口校验。违反其中任何一条都算失败：

- 不直接写数据库，不写一次性导入脚本，不调用旧的 `/api/questions/batch` 接口。
- 不把访问口令打印出来或写进任何文件、对话。

家长说"直接写库就行"时，**仍然走小工具**，并用一句话告诉家长为什么：只有小工具
会校验考点、页码和整卷内容，直接写库会把没校验的数据塞进统计。

## 工作步骤

1. **取资料。** 运行 `guide --subject <学科>`（学科从卷面内容判断）。拿到考点清单、
   错因清单、默认年级学期，以及 `catalog_available`（这个年级有没有考点目录）。
2. **判错**（见下一节）。只录错题。
3. **写每道题**：第几张照片、题号、题干、正确答案、解析、孩子的答案、判错依据、
   错因、考点。字段怎么填看 `payload-format.md`。
4. **问家长一次**（见"如果……就……"）。
5. **上传照片。** 运行 `upload 照片1 照片2 ...`，把返回的路径按页顺序填进 `paper.images`。
6. **提交。** 把内容写成一个 JSON 文件，先 `check <文件>`，按退出码处理，通过后 `submit <文件>`。
7. **汇报**（见最后一节）。

## 判错：每道题先自己做一遍，再看符号

不同老师的批改符号含义不一样（真实卷子里：数学老师的长斜线表示"对"，英语老师划在
选项上的斜线表示"错"）。所以**先自己把这道题做一遍，用你的结果去理解这位老师的符号
是什么意思，不能只凭符号的形状。** 然后按下表处理：

| 老师的批改 vs 你自己的验算 | 怎么做 |
| --- | --- |
| 符号表示错，你验算也是错 | 录入 |
| 符号表示对，你验算也是对 | 不录 |
| 符号和你的验算对不上 | 录入，标待核对 `wrong_unclear`，说明里写清哪里对不上 |
| 老师没有批改，你验算发现写错了 | 录入，标待核对 `wrong_unclear`，说明里写"老师没有批改这一题" |
| 老师没有批改，你验算是对的 | 不录 |

孩子的答案（`wrong_answer`）从卷面照抄，**看不清就留空，绝不编造**。留空不会让这道
题变成待核对；但题干或答案拿不准时，标待核对 `text_unclear`。

## 如果看到 X，就做 Y

- `guide` 的学科列表里没有这份卷子的学科（比如语文）→ 不录，告诉家长这份没有录和原因。
  **不要问家长要不要新建学科，不要把题归到别的学科。**
- `guide` 返回 `catalog_available` 为 false → 不填考点，正常提交，并告诉家长这个年级
  还没有考点目录。
- 考点清单里找不到合适的 → 不填考点，把这题标待核对 `kp_unsure`。
- 家长还没说这是哪份东西，也没说不用问 → 问一次，照原文：
  **"这是哪份作业或卷子？如果是考试，多少分？可以回'跳过'。"** 只问这一次。
- 家长已经说了是哪份、或说了"不用问我" → 不问。家长回"跳过"或没说 → 名称、类型、
  分数都不填，交给系统给默认值。
- 家长说图片不用上传 → `paper.images` 留空，每道题不写 `page`。
- 日期：家长说了、或卷面上印着/写着，才填 `paper_date`；否则不填（系统按今天当录入日）。
- 年级、学期：家长说了、或卷面上印着，才用；否则用 `guide` 返回的默认值。
- 拿不到照片的本机文件路径 → 告诉家长，由家长决定是给出照片位置，还是不带照片录入。

## 遇到这些念头就停下

- "写个脚本 / 用数据库直接插更快" —— 不行，只走小工具。
- "标太多待核对会把队列塞满，这几道就不标了" —— 该标的必须标，漏标才是失败。
- "这个字看不清，但大概是 X，填上去吧" —— 看不清就把 `wrong_answer` 留空。
- "顺手问一下日期 / 要不要新建学科" —— 只问那一句原文，别的都不问。
- "照片上没有年份 / 日期，补上今天吧" —— 不补，`paper_date` 留空。
- "清单里没有合适考点，自己起个名字填进去" —— 不填考点，标 `kp_unsure`。

## 借口与事实

| 基线里出现过的借口 | 事实 |
| --- | --- |
| "Not flagged for review to avoid flooding the queue."（为免塞满队列不标） | 老师没批改却写错的题必须录入并标 `wrong_unclear`，说明写"老师没有批改这一题"。队列本来就是让家长逐题看的，漏标才是真的失败。 |
| "按所见转录"／"把括号里的字母推定为孩子所选" | 看不清就把 `wrong_answer` 留空，不照猜写出来。留空不影响入库。 |
| "要不要先新建'语文'学科再录入？" | 不问也不建。系统没有的学科直接不录，告诉家长原因。 |
| "这份作业是哪天做的、第几学期？" | 只问那一句原文。日期、年级、学期看不出就留空或用默认值，不追问、不推断。 |
| "不能用旧 MySQL MCP / 旧本地脚本写生产"（自己知道，却没告诉家长） | 决定对，但家长说"直接写库"时，必须用一句话告诉家长为什么没那么做。 |

## 退出码怎么处理

- `check` / `submit` 返回 **2**：按返回的 `errors` 逐条改好，再重新提交。
- 返回 **3**：安装的录入规范和服务器版本不一致。告诉家长需要重新运行安装脚本更新，
  **不要绕开它**（比如改版本号、换接口）。
- 返回 **4**：配置、文件或网络问题。把工具给出的那句中文说明原样转告家长。

## 提交成功后汇报

一句话告诉家长：**录了几道、几道直接入库、几道待核对（各自什么原因）**，
并给出待核对页地址 **https://easyfix-bl2.pages.dev/review** 。

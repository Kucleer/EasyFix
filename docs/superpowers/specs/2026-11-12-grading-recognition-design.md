## 1. 为什么做

项目 3 的批改页按手机设计：拍照 → 题号方格默认全对、只点做错的 → 提交。电脑上仍然是旧的批改弹窗（逐题点对错、全部点完才能提交、批改后不能改）。

用户的实际做法（**【用户定】**）：

1. 孩子做完卷子。
2. 家长**先拍照**，这时卷面干净，没有红笔。
3. 系统识别卷面，读出每道题孩子写的答案，和标准答案比对，**预批一轮**。
4. 家长在屏幕上复核：对照标准答案和识别出的孩子答案，改掉误判，提交。
5. 家长照着结果在纸上把错题圈出来，**孩子订正**。订正不进系统。

家长在电脑和手机上都会批，所以批改页要两边都好用。

## 2. 目标、不做的事、要避免的结果

### 目标

1. 所有错题练习卷（考点卷和手动勾题组的卷子）都用同一个批改页 `/grade/:id`，电脑和手机都按正式场景设计。**【用户定】**
2. 拍完照后系统先识别、预批一轮，家长复核后提交。**【用户定】**
3. 复核时每道题都显示标准答案，识别读错时家长能直接看出来、改过来。**【用户定】**
4. 识别在页面上等，有进度条，一份卷子一分钟左右可以接受。**【用户定】**
5. 相似题只根据错题本身出，不根据孩子的错误答案出。**【用户定】**

### 不做

- 不保存识别出来的孩子答案。只在这次复核时显示，提交只写最终对错。**【用户定】**
- 不记录订正。**【用户定】**
- 不做后台排队、离开页面后继续识别。识别时家长留在页面上等。**【用户定】**
- 不为"两个家长同时批同一份卷子"做界面设计。实际不会同时批。**【用户定】** 项目 3 已有的版本号检查（409）保留，防同一个人开两个窗口互相覆盖；界面上只保留现有的"已为你刷新"提示。**【Claude 定】**
- 不读红笔。识别只读孩子的笔迹，所以要在批红笔之前拍。
- 单词练习、阅读练习的批改不动，继续用现有方式。
- 不改识别主机、不换识别模型。

### 要避免的结果

- 识别把做错的题判成对，家长没发现就提交了。对策：每道题都显示标准答案和识别出的孩子答案，判对的题也能一眼扫过。误判本身可以接受。**【用户定】**
- 识别主机关机、断开或出错时，批改卡住、进不去。
- 识别一份卷子调用多次模型，或者重新打开已批改的卷子又识别一遍。
- 已上线的项目 3 批改规则（按差值计数、版本号、"没做""题目有误"、只在第一次批改时发星星）被改坏。

## 3. 批改流程

### 3.1 第一步：拍照

- 和项目 3 现在一样：可以多张，手机调相机或从相册选，上传前压缩，存进 `practice_set.review_images`。
- 电脑上：点按钮选文件，也可以把图片拖进页面。**【Claude 定】**
- 拍完点"开始识别"，进入第二步；也可以点"跳过识别"，直接进复核，按旧方式默认全对。**【Claude 定】**
- 页面上提示一句"请在用红笔批改前拍照"。**【Claude 定】**

### 3.2 第二步：识别和预批（进度条）

- 一页一页识别，每页约 13 秒（读图），全部读完后再做一次比对（约 8–10 秒）。一份 3 页的卷子大约一分钟。数字来自整页识别的实测。
- 进度条按步骤走："正在识别第 2 / 3 页" → "正在比对答案"。前端每完成一步再发下一步的请求，和整页识别录入的推进方式一样，进度是真实的，不是假动画。**【Claude 定】**
- 可以取消，取消后进复核，按默认全对处理。
- **识别失败的兜底**：识别主机不可用、某页读不出来、比对出错或超时，提示"识别没成功，已改为手动批改"，进入复核，按项目 3 原来的默认全对。批改不会卡住。**【Claude 定】** 部分页读出来、部分没读出来时，只对读出来的部分预批，其余题按"拿不准"处理。**【Claude 定】**

### 3.3 第三步：复核

每道题一行（手机上是卡片，电脑上是表格行），显示：

| 内容 | 说明 |
| --- | --- |
| 卷面题号 | 和纸上的号一致，带"原题 / 相似题"标记 |
| 题目 | 默认只露一两行，可展开 |
| **标准答案** | 原题的答案或相似题的答案 |
| **识别出的孩子答案** | 没读到时写"没读到" |
| 预批结果 | 对（绿）/ 错（红）/ 拿不准（黄） |

- 点结果可以在对和错之间切换；另有"没做""题目有误"两个选项，沿用项目 3 的规则（灰色，不计入）。
- **拿不准的题必须点一下**（定成对或错）才能提交。**【Claude 定】** 拿不准包括：没读到孩子答案、识别把握不大。
- 顶部固定显示"错 X、拿不准 Y、共 N"，有一个开关"只看错的和拿不准的"，默认打开，判对的先收起来，随时可展开。**【Claude 定】**
- 排序：按卷面题号，不按对错重排，方便对照纸面。**【Claude 定】**
- **看照片**：电脑宽屏上，左边是题目列表，右边固定显示卷面照片，可切页、放大。手机上点一道题时从底部弹出照片。识别能给出题目在第几页时，自动翻到那一页。**【Claude 定】**
- 没有识别结果（跳过、失败、已批改的卷子）时，"识别出的孩子答案"一列不显示，其他照旧。

### 3.4 第四步：提交和结果

沿用项目 3：按差值计数、版本号检查、结果页显示正确率、考点变化、点亮的星、毕业的题。提交内容和现在完全一样，不多带识别结果。

### 3.5 再次打开

- 已批改的卷子打开后直接进复核，显示上一次提交的对错，**不再识别**。**【Claude 定】** 页顶有"重新识别"按钮，家长确实要时可以手动触发；重新识别的结果只当作参考显示，不自动改掉已提交的对错。**【Claude 定】**
- 没批改过、但识别到一半离开了的卷子：再打开从第一步开始，照片已经存过，不用重拍，点"开始识别"会重新识别。识别结果不存库，所以这里会再调一次模型。**【Claude 定，这种情况不多】**

## 4. 识别和比对怎么做

### 4.1 和录入识别的区别

录入识别要从照片里找出错题、读题干、自己算答案。批改识别简单得多：卷子是系统出的，每个题号对应哪道题、标准答案是什么都已知，只需要**按题号读出孩子写的答案，再和标准答案比**。

### 4.2 步骤

1. **读图**：每张照片调一次识别主机（`ocr_client`，经 Workers VPC 绑定），拿回整页文字。复用 `scan.py` 里读图的做法（从 R2 取图、主机忙时重试、超时）。**普通模式，不做强化重扫**（实测重扫没有看得出的改善，已关闭）。
2. **比对**：所有页读完后，调一次模型（和整页识别同一个模型），输入：
   - 每页的识别文字；
   - 这份卷子每道题的卷面题号、题目、标准答案（服务端从库里取，不从前端传）。
   输出：每个题号一条，`{题号, 孩子答案（读不到为空）, 判定（对 / 错 / 拿不准）, 在第几页}`。判定规则沿用录入识别调好的"只看最终答案"。
3. 服务端对模型输出做清洗：题号必须属于这份卷子；漏掉的题号补成"拿不准"；多出来的丢掉。

### 4.3 数据存不存

- 识别文字和预批结果**都不写库**，接口直接返回给页面，页面在内存里拿着。**【用户定：不保存孩子答案】【Claude 定：识别文字也不存】**
- 所以不需要新表，也不需要数据库迁移。**【Claude 定】**
- 读图一步需要知道读哪张图：传 `review_images` 里的序号，服务端从库里取路径，不接受前端传任意路径。**【Claude 定】**

### 4.4 接口（建议，具体由实施者定）

| 接口 | 作用 |
| --- | --- |
| `POST /api/practice-sets/{id}/recognize/page` | 读一张照片（传照片序号），返回这页的识别文字 |
| `POST /api/practice-sets/{id}/recognize/judge` | 传各页识别文字，服务端取题目和答案，调一次模型，返回每题的预批结果 |

- 只允许 `source_type='question'` 的练习集；已删除 404。
- 识别主机不可用时，读图接口返回明确的"识别不可用"（不是 500），前端走兜底。
- 每份卷子正常批改：读图 N 次（N = 照片数，打到自家主机，不花钱）+ 模型 1 次。

## 5. 电脑和手机共用批改页

- 页面还是项目 3 的 `/grade` 和 `/grade/:id`，改成两种宽度都按正式场景排版。**【用户定】**
- 宽度 ≥ 1024 像素按电脑排：复核时左列表右照片；拍照一步支持拖放。窄屏按手机排。**【Claude 定】**
- 手机上的长按菜单保留；电脑上每行直接显示"没做""题目有误"等选项或一个更多菜单，不靠长按。**【Claude 定】**
- 项目 3 的题号方格视图被第 3.3 节的列表取代。**【Claude 定】** 方格只能看号，放不下标准答案和孩子答案。

## 6. 所有错题练习卷都走新批改页

- 练习中心里，`source_type='question'` 的练习集（不论是不是考点卷）点"批改"都跳到 `/grade/:id`；已批改的显示"改批改"，也能进去改。**【用户定：所有的】**
- 旧的批改弹窗只留给单词和阅读练习集。**【Claude 定】**
- **不考虑旧批改**：旧弹窗里"批改时查看 / 编辑题目、改考点"的功能不搬到新批改页。答案录错的题先标"题目有误"，再去错题页改。以前在旧弹窗里批过的卷子不做兼容处理，和新批的一样可以"改批改"。**【用户定，2026-11-12：现在只有一个用户】**
- 手动组的卷子 PDF 没有项目 3 那样全卷连续的卷面题号。批改页上的题号按练习集里题目的顺序（`display_order`）从 1 编号，必须和这份 PDF 上印的号一致，实施时要核对旧 PDF 的编号方式。**【Claude 定】**
- 打印后有题被删除、或题面换过，纸上的号和批改页可能错开。不为此存打印时的题号；批改页检测到这种情况时提示"题号可能和纸上不一致"，并关闭这份卷子的识别，改为手动批。**【Claude 定】**
- 待批改列表 `/grade` 和首页"专项练习"那一格的计数，项目 3 已经把手动组的卷子算进去了，不用改。

## 7. 相似题不再用错误答案（A 部分，项目 3 上线前改）

**【用户定，2026-11-12】** 相似题只根据错题本身出：原题、答案、考点、有没有图。不给模型孩子当时的错误答案。

- 线上现在的相似题（`main` 分支）本来就没用错误答案，不受影响。
- 项目 3 分支里加进去的要拿掉，见 9.1。
- `question.wrong_answer` 这个字段和录入时记的数据不动，只是相似题提示词不用它。

## 11. 实施说明（和上文不一样或补充的地方）

- 接口：`POST /api/practice-sets/{id}/recognize/page`（`{index}` → `{index, text}`，识别不可用 503）、`POST /api/practice-sets/{id}/recognize/judge`（`{pages: [{index, text}]}` → `{items: [{id, number, student_answer, verdict, page}]}`）。代码在 `cloudflare/src/grading_scan.py`、`grading_model.py`，测试 `cloudflare/scripts/grading_scan_test.py`。
- 开始识别前先查一次识别主机健康（3 秒），不可用直接改为手动批改，不必等每页超时。
- 第 5 节"手机上的长按菜单保留"没有照做：电脑和手机每道题都直接显示"对 / 错"两个按钮，另有"…"菜单放"没做""题目有误""看解析"，比长按直观。
- 拍照一步加了删除单张照片的按钮，拍错的照片会影响识别。
- 第 6 节的题号错开检测：手动组的卷子当前题数比创建时（`total_questions`）少时提示并关闭识别。题面在打印后改过的情况检测不出来。
- "只看错的和拿不准的"按预批时定下的名单筛，改成对的题不会从眼前消失。
- 前端路由加了兜底：发布新版本后，旧页面加载页面文件失败时自动整页刷新一次（`frontend/src/router/index.js`）。

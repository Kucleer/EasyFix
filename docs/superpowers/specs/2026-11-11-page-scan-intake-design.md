# 设计：整页识别录入（网页上传 + 本地 OCR）

日期：2026-11-11
状态：已确认（2026-11-11）
相关文档：`2026-11-11-ocr-host-service-design.md`（主机端开发与配置，单独成文，用户带到那台主机上做）、`ocr-ollama-handoff.md`（那台主机上的 OCR 实测与交接）、`2026-11-10-intake-and-papers-design.md`（项目 1：录入规范与卷子记录）

本文管云端后端、数据库和页面。主机上的识别服务、强化重扫、开机自启和隧道客户端在主机端文档里，两边之间的接口以主机端文档第 4 节为准。

文中每条决定都标了来源：**【用户定】** 是用户在对话中明确说的；**【Claude 定】** 是 Claude 替用户做的选择，用户审阅时可以改。第 15 节把所有 Claude 定的事项列在一起。

## 1. 为什么做

项目 1 做完后，录错题只有一条好走的路：把照片贴给 Claude 或 Codex，由它们看图识别后提交。这条路主要是孩子爸爸在用。

孩子妈妈用手机或电脑打开网页录题时，只有手工录入页（`Upload.vue`）：传一张图，然后题干、答案、解析、考点全部自己打字。一页作业有好几道错题，打字太慢，所以这条路实际上没人用。

另一台常开的 Windows 主机（RTX 4070 Ti 12GB）上已经跑通了本地 OCR 模型，并做过实测（见第 3 节）。这次把它接进来：她传一张整页照片，系统把这一页里做错的题预填好，她核对、修改、确认后入库。整个过程不经过 Claude 或 Codex。

## 2. 目标、不做的事、要避免的结果

### 目标

1. 保留两条路。第一条（Claude / Codex 录题）完全不动；第二条是本文的网页识别录入。**【用户定】**
2. 第二条路：在录入页一次传一张整页照片，系统识别后把这一页的错题预填出来，她在同一页核对、修改、录入，然后传下一张。**【用户定】**
3. 手机和电脑都能用，同一个页面自适应。**【用户定】**
4. 识别用那台主机上的本地 OCR，后端通过隧道连过去，不买域名，主机不对公网开入口。**【用户定】**
5. 主机或隧道不可用时，录入页退回现在的手工录入，不卡住。**【Claude 定】**

### 不做

- 不改第一条路的任何东西：录入规范、小工具、`/api/intake/*` 接口、待核对页、卷子页。
- 不识别红笔批改。OCR 读不出红笔，对错由模型验算判断（见 6.3）。**【用户定】**
- 不自动入库。预填的题都要她点了"录入"才写进错题库。
- 不做一次传多张、后台排队、回头再处理。一次一张，当场整理。**【用户定】**
- 不建卷子记录。这条路录的题和现在手工录入的题一样，"所属卷子"为空（见 9.3）。**【Claude 定】**
- 不裁剪图片。每道题挂的是整页照片。
- 不做重扫超过一次。**【用户定】**
- 不把 OCR 模型搬到云上，不换模型，不调模型参数。

### 要避免的结果（即使功能做出来了也算失败）

- 做对的题混进错题库。
- 读错的内容（比如分母 13 读成 131）没被发现就入库了。
- 她每页要改的东西比自己打字还多。
- 主机关机、隧道断开或模型出错时，录入页打不开或者卡死。
- 主机对公网暴露了入口，或者密钥写进了仓库和文档。

## 5. 整体做法

```
她在录入页选学科，传一张整页照片
        │
        ▼
照片存进 R2（现有上传接口）
        │
        ▼
后端 Worker ──隧道（Workers VPC）──▶ 那台主机的识别服务 ──▶ 本地 OCR 模型
        │                                   │
        │◀────────── 整页文字 ───────────────┘
        ▼
后端调用现有 LLM：拆题、读出孩子的作答、自己验算、判断对错、
                  给做错的题补答案解析、打考点和错因
        │
        ├─ 有异常（公式断了、解不出、串题、缺图形条件）且还没重扫过
        │        └─▶ 让主机做一次强化重扫 ─▶ LLM 结合两份文字再整理一次
        ▼
这一页的草稿：做错的、拿不准的、做对的
        │
        ▼
她在页面上逐题：录入 / 修改后录入 / 不是错题
        │
        ▼
错题库（直接算已通过）   →   传下一张
```

分成五块：录入页、识别流程、主机端识别服务、隧道接入、后端接口和数据库。

## 6. 识别流程

### 6.1 步骤

1. **读图。** 后端从 R2 取出照片，经隧道发给主机的识别服务，拿回整页文字。
2. **整理。** 后端把整页文字、该学科该年级的考点清单、错因清单交给现有的文本模型（设置页里配置的那个，目前是 deepseek-flash），让它一次返回这一页所有题的结构化结果（见 6.2）。
3. **兜底重扫（最多一次）。** 第 2 步的结果里只要有一道题带"读图异常"标记（见 6.4），并且这一页还没重扫过，就让主机做一次强化重扫（见第 7 节），再把两份文字一起交给模型重新整理。重扫之后不管结果如何都不再重扫。**【用户定：最多一次，只做兜底】**
4. **存草稿。** 结果存成这一页的草稿，页面显示出来。

正常情况是第 1、2、4 步，一遍过。

### 6.2 模型要返回的内容

对这一页识别出的每一道题：

| 字段 | 含义 |
| --- | --- |
| 题号 | 卷面上印的题号，照原样 |
| 题干 | 完整题干，数学公式按现有规范写（行内 `\(...\)`，独立 `\[...\]`） |
| 孩子的答案 | OCR 读到的孩子作答，读不出就留空 |
| 判断 | `wrong` 做错了 / `right` 做对了 / `unsure` 拿不准 |
| 判断理由 | 一句话，如"孩子写 x²+3，应为 x³−3" |
| 读图异常 | 0 个或多个标记，见 6.4 |

判断为 `wrong` 或 `unsure` 的题，再加上：正确答案、解析、主考点和关联考点（只能从给它的清单里选编号）、错因（只能从清单里选）、难度（1–5）。

判断为 `right` 的题只返回题号、题干开头（不超过 40 个字）和判断，不要完整题干，也不补答案解析。**【Claude 定】** 理由：一页可能有二十来道小题，全部写完整会很慢，还可能超出模型一次能返回的长度。她点"补成错题"时再单独补全那一道（见 8.4）。

现有的模型调用函数（`settings.py` 的 `generate_json`）把返回长度上限和随机度写死了。实施者可以给它加可选参数（这条路用更低的随机度），不传时行为不变，不影响相似题和学习报告。模型返回的内容被截断或不是有效内容时，按模型失败处理（9.5）。

后端对模型返回的内容做清洗，不信任它：考点编号不在清单里的丢掉；错因不在清单里的丢掉；难度不在 1–5 的改成 3；字段类型不对的那道题整道标为"拿不准"。清洗规则写成纯函数，方便测试。

### 6.3 怎么判断做错了

模型自己把题做一遍，和 OCR 读到的孩子作答比对：**【用户定：不依赖红笔】**

- 孩子的作答读得出、和模型算的不一样：`wrong`。
- 孩子的作答读得出、和模型算的一样：`right`。
- 孩子的作答读不出，或者这道题模型自己解不出，或者是没有标准答案的题型（作图、作文、开放题）：`unsure`。
- 孩子没有作答（空着）：`wrong`，判断理由写"没有作答"。**【Claude 定】**

提示词里要写明这几条，并且要求：不许猜孩子写了什么；只是书写形式不同（比如 0.5 和 1/2）不算错。

### 6.4 读图异常标记

模型从文字上看得出不对劲时打标记。标记只有四种，对应交接文档里的已知读错类型：

| 标记 | 含义 | 页面上的提示 |
| --- | --- | --- |
| `broken_formula` | 公式或算式不完整、括号不配对、数字明显不合理 | 公式可能读错，请对照原图 |
| `unsolvable` | 按读到的题干解不出，或条件不够 | 题干可能缺内容，请对照原图 |
| `merged` | 像是两道题或题干和演算混在了一起 | 可能串题，请对照原图 |
| `figure_needed` | 题目依赖图形或表格，但文字里没有相应条件 | 这题有图，请对照原图补条件 |

要说清楚的一点：这些标记只能发现"看得出不对劲"的读错。读错了但题目照样能算的情况（比如 13 读成 131，题目仍然成立）模型发现不了，只能靠她对照原图。所以原图必须一直在她眼前（见第 8 节）。

### 6.5 耗时

- 目标：不重扫时一页从传完到出结果，中位数不超过 30 秒；重扫时不超过 60 秒。**【Claude 定】**
- 依据：读图约 5 秒；模型整理一整页比实测里的单题（3.24 秒）要慢，实际多少在验收时测。
- 页面在等待时显示当前在做哪一步（"正在读图""正在整理题目""正在重扫一次"），原图先显示出来。

## 7. 主机端识别服务（摘要）

主机上的开发和配置单独成文：`2026-11-11-ocr-host-service-design.md`，由用户带到那台主机上做。**【用户定】** 这里只列云端需要知道的部分，细节和两边的接口约定以那份文档第 4 节为准。

- 主机上除了已有的 Ollama，再跑一个很小的识别服务，只监听 `127.0.0.1:11436`。它收一张图，按实测时的做法（`official_backend.py` 的图片预处理和非思考提示词）调本机 Ollama，返回文字。后端不直接调 Ollama：图片预处理和强化重扫要在主机上处理图片，后端也不需要知道模型的提示词和参数。**【Claude 定】**
- 两个接口：`GET /health`（2 秒内返回，不触发推理）和 `POST /ocr`（请求体是图片原始字节，`Content-Type` 是图片类型，参数 `mode` 为 `normal` 或 `enhanced`）。
- 每个请求带请求头 `X-EasyFix-OCR-Key`，值是共享口令。口令存在主机的配置文件和后端 Worker 的密钥里。隧道本身已经只有后端能连，口令是第二道保险。
- 成功时返回 `ok`、`contract`（约定版本，目前是 1）、`mode`、`text`（整页文字）、`segments`（分段文字）、`elapsed_ms`、`model`。失败时返回 `ok: false`、`code`、`detail`，状态码和 `code` 的对照见主机端文档 4.3。
- 主机一次只处理一张图，最多排 2 个，排满或排队超过 20 秒返回 503 `busy`。`normal` 模式单张处理时限 45 秒，`enhanced` 模式 90 秒。
- 照片方向由主机负责：识别前先按照片里的方向标记把图转正。后端和页面原样传图，不转不裁。**【Claude 定】**
- 现有上传接口会把 `image/jpg` 原样存下来。后端转发给主机时，把图片类型统一成 `image/jpeg`、`image/png`、`image/webp` 三种之一。
- 强化重扫（`enhanced`）的做法是把整页切成上下几条有重叠的横条，分别识别后按顺序返回。同一张图同样的设置再读一遍结果基本不变，所以重扫必须换读法。**【Claude 定】** 具体参数在主机上用 20 张回归图调，以那 6 道关键读错的题为靶子。如果一道都救不回，由用户决定换做法还是去掉重扫；后端要留一个开关，能关掉重扫这一步。
- 主机做完后回传：VPC 服务编号、和约定有出入的地方、两种模式的用时、重扫的回归结果（主机端文档第 9 节）。

后端对主机返回的处理：

- `contract` 不是 1：当作识别服务不可用，提示文字写明"识别服务版本不一致"。
- 503 `busy`：等 2 秒重试，最多 3 次，仍然忙就按读图失败处理。
- 其他失败：按 9.5 处理，把 `detail` 记进这一页的 `error`，不原样显示给用户（页面用自己的提示文字）。
- 后端调主机的超时统一为 120 秒（主机最坏情况是排队 20 秒加处理 90 秒）。

几个时限放在一起看，保证正常的慢步骤不会被误判成卡住：主机单次最多 110 秒 < 后端调主机 120 秒、后端调模型 120 秒（现有值）< 页面等一步 150 秒 < 判定卡住 180 秒。页面现有的请求默认 60 秒超时，"推进一步"这个请求要单独设成 150 秒。

## 8. 录入页

### 8.1 位置

就是现在的"录入错题"页（`/upload`，`Upload.vue`）。入口不变。**【用户定：在现有录入页上做，OCR 是预填】**

### 8.2 四个状态

| 状态 | 页面 |
| --- | --- |
| 选图 | 选学科、年级、学期（沿用上次的选择），选一张图或拍照。下面有"不识别，直接手工录一道"入口，点了就是现在的手工表单 |
| 识别中 | 原图已经显示出来，旁边显示进行到哪一步。可以点"取消，改为手工录" |
| 整理 | 见 8.3 |
| 完成 | 点"下一张"回到选图状态，学科年级学期保留 |

### 8.4 列表里放什么

- **主列表**：判断为"做错了"和"拿不准"的题，按卷面顺序。拿不准的题带黄色提示，写明原因（比如"没看清孩子的答案，请对照原图判断"）。**【Claude 定：拿不准的也放主列表】**
- **折叠区"模型认为做对的 N 道"**：默认收起。展开后每道一行（题号和题干开头），每行有"补成错题"按钮，点了就移到主列表，并在后台请模型补全这一道：把整页文字和这道题的题号交给模型，让它返回这道题的完整题干、孩子的答案、正确答案、解析、考点、错因（只针对这一道，调用一次）。补全失败时卡片直接进入修改状态，由她自己填。
- **"手工加一道"**：识别完全漏掉的题，点了在主列表末尾加一张空白的编辑卡片。

### 8.5 每道题的卡片

平时是只读的：题号、题干、孩子的答案、正确答案、考点、错因，公式用现有的 `MathText` 显示。解析不默认显示，点"修改"后能看到和改。

右下角三个小按钮，从左到右：**【用户定：保留修改按钮，按钮要小】**

| 按钮 | 样式 | 作用 |
| --- | --- | --- |
| 不是错题 | 文字按钮 | 从列表里去掉，不入库。不用二次确认，去掉后页面底部给一个"撤销"提示，几秒内可以恢复 |
| 修改 | 普通小按钮 | 卡片变成表单：题号、题干、孩子的答案、正确答案、解析、考点（现有的 `KnowledgePointPicker`）、错因、难度。底部是"取消"和"保存"。保存后回到只读状态，不自动录入 |
| 录入 | 主色小按钮 | 把这道题写进错题库。成功后卡片收成一行"第 3 题 已录入"，带"撤回"（见 9.4） |

- 带"读图异常"提示的题，第一次点"录入"时弹一句确认："这道题可能读错了，对照过原图了吗？"确认后才录入。点过"修改"并保存的题不再弹。**【Claude 定】**
- 录入被后端拒绝时（比如公式写坏了、选了考点但没选主考点），卡片自动切到修改状态，把后端的提示显示在卡片顶部。

### 8.6 底部两个按钮

- **全部录入**：把主列表里"做错了"且没有读图异常提示的题依次录入。拿不准的和带提示的不包含在内，要逐道处理。按钮上显示数量，如"全部录入（1）"。录入过程中显示进度，某一道被拒绝时停下来，那张卡片切到修改状态并显示原因。**【Claude 定】**
- **下一张**：回到选图状态。主列表里还有没处理的题时，先问一句"还有 2 道没处理，不要了吗？"，确认后这一页结束，没处理的题不入库。

### 8.7 没整理完就离开

识别结果存在后端，不在浏览器里。她中途关掉页面，下次打开录入页时顶部显示"上次有一张图没整理完"，可以"继续"或"不要了"。识别到一半离开的，回来点"继续"会从断掉的那一步接着做。

### 8.8 样式

沿用现有做法：`PageHeading`、`MathText`、`MathEditor`、`KnowledgePointPicker`、`el-image`，768px 断点。按钮用 Element Plus 的 `small` 尺寸，右对齐，一张卡片里只有一个主色按钮。

## 9. 后端接口和数据库

### 9.1 新表 `scan_page`（迁移 `0014`）

一张上传的图是一条记录。只加表，不改现有表。**【Claude 定】** 表名、列名是 Claude 定的。

| 列 | 含义 |
| --- | --- |
| `id` | 主键 |
| `student_id` | 学生，默认 1，取值方式和项目 1 相同（"当前学生"函数） |
| `subject_id`、`grade`、`semester` | 上传时选的学科、年级、学期 |
| `image` | 照片在 R2 的存储路径 |
| `status` | `uploaded` 已上传 / `reading` 读图中 / `analyzing` 整理中 / `rescanning` 重扫中 / `ready` 可以整理 / `failed` 识别失败 / `closed` 已结束 |
| `step_started_at` | 当前这一步什么时候开始的，用来判断是不是卡住了 |
| `ocr_text`、`ocr_text_enhanced` | 第一次读图和重扫的文字 |
| `rescan_used` | 是否已经重扫过，0 或 1 |
| `items` | 这一页的题目草稿，JSON 数组。每项是 6.2 的字段，加上：序号、状态（`open` 未处理 / `accepted` 已录入 / `dismissed` 已去掉）、录入后的错题编号、是否被人改过 |
| `error` | 失败时给用户看的一句话 |
| `timings` | 各步骤用时，JSON，验收和排查用 |
| `deleted`、`created_at`、`updated_at` | 软删除和时间 |

索引：`scan_page(student_id, status)`，只索引未删除的行。

### 9.2 接口

新模块 `cloudflare/src/scan.py`（接口）和 `cloudflare/src/scan_model.py`（纯规则函数：拼提示词、清洗模型返回、判断要不要重扫、分组）。鉴权沿用现有的登录会话。接口路径、字段名由实施者定，下面只规定行为。

| 接口 | 行为 |
| --- | --- |
| 查识别服务是否可用 | 后端经隧道调主机的 `/health`，3 秒超时。返回可用或不可用，不把主机的任何细节透给前端 |
| 新建一页 | 输入：已上传照片的路径、学科、年级、学期。照片路径格式用项目 1 的同一条规则检查。建一条 `uploaded` 记录并返回 |
| 推进一步 | 页面反复调这个接口，每次后端只做当前状态的下一步（读图 → 整理 → 需要时重扫 → 再整理 → `ready`），做完返回新状态和这一步的结果。同一页同一时刻只能有一个推进在跑：靠 `step_started_at` 加条件更新实现，另一个请求进来时返回"正在处理"；一步超过 180 秒没结束视为卡住，允许重新做 |
| 查一页 | 返回状态和草稿，用于刷新和继续 |
| 查没整理完的页 | 返回当前学生状态不是 `closed`、`failed` 的页，最多最近 5 条 |
| 录入一道 | 输入：页编号、题目序号、最终字段。规则见 9.3。同一道已经录入过的，直接返回上次的结果，不重复写 |
| 去掉一道 / 恢复一道 | 改草稿里那一项的状态 |
| 补成错题 | 对折叠区里的一道题调一次模型，补答案、解析、考点、错因，移到主列表 |
| 保存修改 | 把她改过的字段存回草稿，标记"被人改过" |
| 撤回录入 | 见 9.4 |
| 结束一页 | 状态改为 `closed` |

"推进一步"分步做而不是一个请求做完的原因：每个请求短，手机锁屏或切走时最多丢一步，回来接着做；页面能显示进行到哪一步。**【Claude 定】**

排除在"每次成功的写请求后刷新缓存版本并记操作日志"之外的：查识别服务、推进一步、保存修改、去掉、恢复、补成错题。这些不改错题库。录入和撤回照常记。现有中间件的排除名单是按完整路径逐个比对的（`auth.py`），新接口的路径里带页编号，要改成按路径开头判断，改的时候不能影响现有的排除项。

"全部录入"不单独做接口：页面按顺序逐道调"录入一道"，显示进度，哪道失败就停在哪道并显示原因，已成功的不受影响。原因：免费计划对一次请求里的数据库操作次数有上限，一次录多道容易超。**【Claude 定】**

"录入一道"要保证不重复写：现有的保存逻辑自己提交一批语句，和草稿状态的更新不在同一批里。实施者可以给保存逻辑加一个可选的"附带语句"参数，把"草稿这一项标为已录入"放进同一批；不传时行为不变。

### 9.3 录入一道题的规则

- 复用现有的错题保存逻辑（`questions.py` 的 `save`），所以校验和手工录入完全一样：学科存在、年级学期难度范围、数学题的公式校验、选了考点就必须有主考点。保存逻辑的允许清单里已经有孩子的答案和题号，只缺判错依据，把它补进去。
- 写入的内容：题干、正确答案、解析、难度、错因、考点、孩子的答案、题号；学科年级学期取这一页的；原图填这一页的照片；判错依据填"页面识别，家长确认"；状态是已通过（`approved`）。
- 不进待核对。理由：待核对是给"没人看过的题"用的，这里每道题都是她看过才点的录入。**【Claude 定】**
- 不建卷子记录，`paper_id` 为空，和现在手工录入的题一样。项目 1 的设计已经允许"没有卷子的题"长期存在。**【Claude 定】** 代价：这些题在"卷子和作业"页里看不到，只在错题列表里。以后想按天归成一份作业，可以单独再做。
- 考点可以不选（记为未分类），和现在手工录入一致。

### 9.4 撤回

刚录入的题发现录错了，可以在卡片上点"撤回"：软删除这道错题，草稿里这一项回到未处理状态。只对这一页里录入的题有效，页结束后要改就去错题列表。**【Claude 定】**

### 9.5 识别失败时

| 情况 | 页面表现 |
| --- | --- |
| 进入页面时主机连不上 | 顶部提示，传图后直接手工录 |
| 读图这一步失败或超时 | 提示"读图没成功"，两个按钮："再试一次""改为手工录" |
| 模型没配置、余额不足、返回的不是有效内容 | 提示原因（沿用现有文本模型的报错文字），两个按钮同上。读图的结果保留，再试时不重新读图 |
| 整页一道题都没识别出来 | 提示"没有识别出题目"，可以手工加一道或换一张 |
| 这一页全都做对了 | 主列表为空，显示"模型没发现做错的题"，折叠区自动展开 |

改为手工录时，照片保留，右边变成现在的空白表单。

## 10. 隧道接入

### 10.1 用什么

用 Cloudflare 的 Workers VPC：在自己的 Cloudflare 账号里建一条隧道，主机上装 `cloudflared` 连上去，再把主机上的识别服务登记成一个"VPC 服务"，绑定给后端 Worker。Worker 通过这个绑定调主机。**【用户定：走隧道、不买域名；具体用 Workers VPC 是 Claude 查文档后定的】**

- 不需要域名，主机没有任何公网地址，只有绑定了的 Worker 能连。
- 官方文档写明免费计划可用，测试期间不收费。
- 主机上的 `cloudflared` 版本要不低于 2025.7.0，主机要能向外发 UDP 7844 端口的流量。建隧道、装 `cloudflared`、登记 VPC 服务在主机端文档第 7 节。
- 不用"临时隧道"（`trycloudflare.com`）：它每次重启地址都变，只用于测试，而且它的保护方式程序过不去。

### 10.2 要先验证的事

Workers VPC 还是测试版，而且文档里只有 JavaScript 的例子，后端是 Python Worker。所以实施的第一步是一次很短的连通性试验，通了再做别的：

1. 主机端先做完识别服务的 `normal` 模式、隧道和 VPC 服务登记，回传服务编号。
2. 用户在后端 Worker 的密钥里填识别服务的口令（主机的 `/health` 也要口令）。给后端 Worker 加绑定，写一个临时接口调主机的 `/health`，再转发一张真实照片调一次 `/ocr`。
3. 在正式环境的 Worker 上确认能通，并记下一次调用的用时。这一步要部署后端，先问用户。

如果 Python Worker 用不了这个绑定：加一个很小的 JavaScript 内部 Worker 专门转发，后端通过服务绑定调它，和现在 PDF Worker 的做法一样。**【Claude 定】**

如果 Workers VPC 整个走不通，或者以后正式版要收费：退回"主机主动来领任务"的做法，主机上的识别服务定时问后端有没有 `uploaded` 的页。`scan_page` 表和"推进一步"的状态设计不用改，只是读图这一步换成主机来做。这条退路这次不实现，只保证不堵死。

### 10.3 密钥

- 隧道的连接口令只存在主机上。
- 识别服务的共享口令：主机的配置文件和后端 Worker 的密钥，由用户自己在两边各填一次。
- 都不进仓库，不写进任何文档、对话和日志。

## 11. 约束

- 正式环境是 Cloudflare（`cloudflare/src/`、D1、R2）。`backend/app/` 是旧本地版，不改。
- 保持 Workers 免费计划。识别一页的子请求数控制在十几个以内（取图、读图一到两次、模型一到两次、公式校验）。
- 数据库只追加迁移，所有新表带软删除。
- 第一条路的代码和接口不改。和它共用的函数（照片路径格式检查、考点清单读取、当前学生）只调用，不改行为。
- 孩子的作业照片只在自己的 R2 和自己的主机之间走。发给模型服务商的只有 OCR 出来的文字，和现在相似题、学习报告用模型的方式一样。
- 代码规范：变量小写下划线，函数前写中文文档字符串，复杂逻辑加中文行内注释。
- 用户是编程初学者：页面文案、报错提示、安装文档都用直白的中文，不用术语。
- 每一步动正式环境、动 Cloudflare 账号、动那台主机之前，都要先得到用户明确同意。

### 12.2 实测验收

1. **回归图跑一遍。** 用那台主机上现成的 20 张回归图走完整流程（读图、整理、兜底重扫），对照交接文档里人工核对过的 61 道目标题，数出并记录：
   - 关键题干完全正确的道数、有关键错误的道数（和交接文档的 41 / 6 比）；
   - 模型判断做错、且确实做错的道数；
   - 做错了但被判成做对的道数（漏判）；
   - 做对了但被判成做错的道数（误判）；
   - 重扫触发了几页、救回了几道关键读错的题；
   - 每页用时的中位数和最大值。

   跑法：云端这边写一个验收脚本，用户带到主机上跑。脚本直接调主机上真的识别服务和真的文本模型，对 20 张图依次走"读图、整理、需要时重扫"，把每页的草稿和各步用时存成文件。为了让脚本走的流程和线上完全一样，"读图、整理、重扫"的先后顺序和判断写成 `scan_model.py` 里的一个函数，读图和调模型由外面传进来；后端和验收脚本都用这个函数。脚本只依赖主机上已有的 httpx，不需要装别的。文本模型的地址和密钥从主机本机的配置文件读，不进仓库。

   对照由人工做：脚本另外生成一张对照表（每页一段，列出模型判错的题、拿不准的题、判对的题），用户对着原图和交接文档里的逐题评分数出上面几项。

   61 道目标题都是错题库里现有的错题，所以它们就是"确实做错"的标准：目标题被模型判成做对的，算漏判。**【用户定】** 模型判错但不在 61 道里的题，可能是误判，也可能是当初没录的错题，要对着原图看一眼才能定。

   这些数字不设及格线，写进验收记录交给用户，由用户决定是否给妈妈用。**【Claude 定】** 图片和结果只留在那台主机被忽略的目录里，不进仓库。
2. **手机走一遍。** 用妈妈平时用的手机，传一页真实作业，从传图到录入、修改、去掉、补成错题、下一张走完。
3. **电脑走一遍。** 同样的流程，确认左图右列表、原图固定和放大。
4. **断开试一遍。** 关掉主机上的识别服务，确认页面提示并能手工录；识别到一半关掉页面再打开，确认能继续。
5. **确认第一条路没受影响。** 用 Claude 录一份卷子，照常入库。

## 13. 实施与发布步骤

每一步动正式环境、Cloudflare 账号或那台主机之前都要先问用户。

两边可以同时开工：主机端按主机端文档做，云端按本文做。接口约定已经写定，任何一边要改都得先告诉用户、两边一起改。云端开发和自动测试用假的主机，不依赖主机端做完。

| 顺序 | 在哪做 | 做什么 |
| --- | --- | --- |
| 1 | 主机 | 识别服务的 `normal` 模式、隧道客户端、登记 VPC 服务，回传服务编号（主机端文档第 2、7 节） |
| 2 | 云端 | 连通性试验（10.2）：用户先在后端 Worker 的密钥里填识别服务的口令；后端 Worker 加绑定，调通主机的 `/health`，再用一张真实照片调一次 `/ocr`，确认大请求和几秒钟的请求都能过。不通就按 10.2 的退路处理，先回来和用户商量 |
| 3 | 云端 | 后端接口、数据库迁移、页面，自动测试全部通过（可以和第 1、2 步同时进行） |
| 4 | 主机 | 强化重扫调试、开机自启，回传回归结果 |
| 5 | 云端 | 导出正式库备份，在备份副本上演练迁移 `0014`，再在正式库执行 |
| 6 | 云端 | 部署后端，再部署前端 |
| 7 | 两边 | 实测验收（12.2） |
| 8 | 云端 | 把结果记进 `docs/cloudflare-migration-status.md`，更新 `ocr-ollama-handoff.md` 里过期的"对接边界"一节 |

连通性试验排在云端所有正式环境改动的最前面。在它通过之前，云端只做本机开发和测试，不动正式环境。

提示词的样本：用户稍后会从主机拷几页真实的 OCR 文字到这台机器被 Git 忽略的目录里。**【用户定】** 样本到之前，提示词和清洗规则先按 6.2–6.4 的规则写，测试用手写的假文字；样本到了之后用它们调一轮提示词，再进入验收。样本只留在被忽略的目录里，不进仓库，不写进测试夹具。

## 14. 风险

| 风险 | 应对 |
| --- | --- |
| Workers VPC 是测试版，接口可能变，正式版可能收费 | 第一步先试；Python 不行用 JavaScript 转发；整体不行退回主机领任务（10.2） |
| 手写作答读错，导致误判或漏判 | 每道题都要她确认才入库；判对的题可以展开补录；验收时数出误判和漏判 |
| 读错但看不出来的内容入库 | 原图一直在眼前；带提示的题录入前多问一句；不能完全杜绝 |
| 模型把题算错 | 她看到的正确答案和解析可能是错的，修改按钮可以改；和现在相似题生成的风险相同 |
| 免费计划对单次请求的计算时间有限制 | 分步推进，每步主要在等外部返回；试验时记下用时 |
| 主机重启后服务没起来 | 开机自启；页面有不可用提示和手工录的退路 |
| 手机照片超过 10MB 或格式不支持 | 超过上限时前端先压缩再传；只在超限时压缩，避免影响识别。具体做法由实施者定 |

## 15. Claude 定的事项（请用户过目）

1. 这条路录的题不建卷子记录，"所属卷子"为空（9.3）。
2. 她确认录入的题直接算已通过，不进待核对（9.3）。
3. 拿不准的题放在主列表里，带黄色提示；做对的折叠（8.4）。
4. "全部录入"只包含"做错了"且没有读图提示的题（8.6）。
5. 带读图提示的题，录入前多问一句"对照过原图了吗"（8.5）。
6. 孩子空着没答的题按做错处理（6.3）。
7. "不是错题"不用二次确认，给一个几秒内的撤销（8.5）。
8. 刚录入的题可以在这一页撤回（9.4）。
9. 不限学科：系统里有的学科都能用这条路，但验收只在数学上做，其他学科识别效果没测过。
10. 识别分步推进，每步一个请求（9.2）。
11. 主机上多跑一个小的识别服务，后端不直接调 Ollama（第 7 节）。
12. 强化重扫的做法是把整页切成几条分别识别（第 7 节，细节在主机端文档第 5 节）。
13. 耗时目标：一页中位数不超过 30 秒，重扫时不超过 60 秒（6.5）。
14. 验收数字不设及格线，由用户看了决定（12.2）。
15. Workers VPC 走不通时的两级退路（10.2）。
16. 模型判对的题只返回题号和题干开头，点"补成错题"时再补全（6.2、8.4）。
17. 照片方向由主机在识别前转正（第 7 节）。
18. "全部录入"由页面逐道调用，不做一次录多道的接口（9.2）。

## 1. 为什么做

路线图的环是"收集错题 → 整理薄弱 → 针对练习 → 看到提升"。项目 1 解决了收集，项目 2 解决了整理（每个考点有了掌握度）。现在缺的是"针对练习"这一步：

- 现在的自动组卷（`practices.py` 的 `generate-from-questions`）只按"没复习过 → 正确率低 → 随机"选题，**不看考点**，也不知道哪道题该复习了。
- 错题没有复习安排。一道题练过一次以后，系统不知道什么时候该再练。
- 相似题每道错题只生成一次、之后一直复用同一道，提示词里没有孩子当时写的错误答案，也没有保存解析。
- 练习卷的 PDF 是一道接一道排下来的，没有按考点分组，没有答案页。
- 批改只有电脑上的弹窗。每提交一次，错题的复习次数就加一次，两个人各批一遍会重复计数。
- 项目 2 已经约定：**让考点变好的证据只来自练习卷里做对**。所以练习卷不做起来，星空上的星就亮不了。

## 2. 目标、不做的事、要避免的结果

### 目标

1. **一键出卷**：家长想出卷时点一下，自己定题量；系统按考点掌握度和复习安排自动选题，家长看一眼预览就能打印。
2. **错题有复习安排**：做错了下一份卷子换成相似题再来，连续做对 2 次后毕业，之后只用于验收和偶尔抽查。
3. **卷面适合打印**：按考点分组，题号连续，答案和解析单独成页。
4. **相似题更有针对性**：提示词带上考点，只根据错题本身出（不用孩子的错误答案，也不用错因），并保存解析。（2026-11-12 修订，见 `2026-11-12-grading-recognition-design.md` 第 7 节）
5. **手机批改几分钟完成**：拍照留存，默认全对、只点做错的题。
6. **批改不重复计数**：一人提交后另一人看到的是结果，可以改，但次数不会多算。
7. 入口尽量少：首页不新增入口，出卷页替换掉旧的"生成练习"按钮。

### 不做

- 不做手写识别批改。**【路线图】**
- 不做定时自动出卷，也不规定"每周一份"。什么时候出、出几道，都由家长手动决定。**【用户定，2026-11-12】**
- 卷子上不印二维码。**【用户定，2026-11-12】**
- 不按天数给错题排复习间隔，隔多久再练由家长出卷的时间决定。**【用户定，2026-11-12】**
- 不让模型凭考点"凭空出新题"（没有对应错题的考点不出题）。**【用户定，2026-11-12】**
- 不把单词、词组和阅读放进考点卷：单词有默写，阅读有阅读练习。
- 不处理五年级的 206 道旧题（没有归到两级考点，算不出掌握度）。
- 不改首页整体版式（那是项目 5），也不在首页新增入口。**【用户定，2026-11-12】**
- 不做周报（那是项目 4）。
- 不记录错因：批改时不选错因，相似题提示词也不用错因。错因大多是模型猜的，不可靠。**【用户定，2026-11-12】** 系统里现有的错因一并停用，范围见第 15 节。
- 不做多学生界面，新列照旧带 `student_id`。

### 要避免的结果

- 卷子太长或全是难题，孩子抵触。题量由家长定，同一考点一般不超过 3 道。
- 同一道题每次出卷都出现。连续做对后要"毕业"；还在待批改卷子里的题不再选。
- 相似题的答案是错的，家长照着批改，把掌握度带偏。批改时要能标"题目有误"，这道题不计入。
- 没学过的考点进了卷子。
- 两个人批改同一份卷子，次数被算两遍。
- 一次出卷调用很多次模型、反复生成 PDF，超出 Workers 免费计划。

## 3. 一次练习的流程

1. **家长出卷**（什么时候出由家长定）：在练习中心或错题列表点"出练习卷"→ 选科目、填题量 → 看到系统选好的题（每题标着为什么选它）→ 可以换题、删题、改题量 → 点"生成并打印"。系统准备相似题、生成 PDF。
2. **孩子做卷**：纸质。做多久取决于家长定的题量。
3. **家长批改**：对着 PDF 最后的答案页在纸上判对错 → 手机上从首页的"专项练习"进待批改 → 拍下卷面 → 把做错的题号点红 → 提交。
4. **系统更新**：掌握度变化、每道题是否毕业，都从批改结果算出来。星空页的点亮时刻照常播放。
5. **另一位家长**打开同一份卷子，看到的是已批改的结果，可以改，不会重复计数。

## 4. 错题的复习安排

### 4.1 规则

每道错题根据它在**练习卷里的批改结果**算出当前状态。原题和相似题的结果都算在这道错题上（现有做法，项目 2 的掌握度也是这样算的）。错题复习页面上点的对错不算（沿用项目 2 的用户决定）。

| 情况 | 状态 | 能不能再出 | 下次出什么 |
|------|------|------------|------------|
| 从没在练习卷里做过 | 待重做 | 能 | 原题 |
| 最近一次做错 | 待重做 | 能 | 相似题 |
| 最近连续做对 1 次 | 巩固中 | 能 | 相似题 |
| 最近连续做对 2 次或更多 | 已毕业 | 不再作为常规题出，只用于验收和抽查（4.4） | 相似题 |

- **不按天数安排间隔**。一道题没毕业就随时可以再出，隔多久再练由家长通过"什么时候出卷"来控制。路线图原来写的"复用单词的间隔逻辑"不再采用。**【用户定，2026-11-12】**
- **连续做对 2 次就毕业**，毕业后不再作为常规题出。**【用户定，2026-11-12】** 也就是一道错题最少做两份卷子：一次原题、一次相似题。这个次数做成常量，以后可以改。
- 毕业的题还会以两种方式出现：考点点亮前的"验收"，和考点掌握后的"抽查"（4.4）。**【用户定方向，2026-11-12】**
- 中途做错一次，连对次数清零，重新数。毕业后这道题又做错（验收或抽查做错，或者家长手动把它加进练习集后做错），同样清零，回到"上次做错"。**【Claude 定】**
- 因为没有间隔，刚做对的题理论上可以马上再出。5.3 的选题顺序把"巩固中"的题排在最后，并且上次练习离现在久的优先，所以只有在别的题不够时才会连着出。**【Claude 定】**
- "第一次重做用原题，之后都用相似题"：第一次是检查订正有没有真的弄懂；之后再用原题，孩子可能是背下了答案。**【用户定，2026-11-12】**
- 标了"没做"或"题目有误"的结果不算对也不算错，状态不变。

### 4.2 读取时现算，不存结果

复习状态**每次读取时从批改记录现算**，不在错题表上存"下次复习时间"。**【Claude 定】**

理由：

- 和项目 2 的掌握度是同一个做法，规则以后要调（比如毕业需要连对几次），改一个常量就行，不用回填数据。
- 改批改结果时不会留下算错的旧状态。如果把"连对几次"存在表里，改一次批改就要想办法把上一次的修改"退回去"。
- 数据量很小：约 600 道错题、约 700 条练习结果，一条 SQL 就能全取出来。

规则写成纯函数，放在新文件 `cloudflare/src/targeted_model.py`，和 `mastery_model.py` 一样不读数据库、不读时钟。

### 4.3 上线那一刻

现有的 600 多道题大多数从没在练习卷里做过，上线后会全部是"待重做"。这不是问题：每份卷子的题量是家长定的，由第 5 节的规则按考点薄弱程度挑。首页不显示"有多少道待重做"这个数字，避免一上来就是几百。**【Claude 定】**

### 4.4 考点状态怎么变（要改项目 2 已上线的规则）

错题和考点是两个维度。**【用户定，2026-11-12】** 错题的维度是"这道题会不会做了"（4.1，连对 2 次毕业）；考点的维度是"这个知识点掌握得怎么样"。两边各用各的规则，不靠把两个数字改成一样来对齐，而是靠下面四条连起来。**【Claude 提议；用户 2026-11-12 看过，没有提出异议】**

掌握度的基础算法不变（项目 2 第 4 节）：学过的考点从 0.5 起步，错一次减 0.15，对一次加 0.15，范围 0.15–0.99，颜色按数值连续渐变。新增：

1. **没清的错题压住上限**：考点下每有一道"待重做"的错题（没在练习卷里做过，或最近一次做错），掌握度的上限就降 0.15。上限 = 1 − 0.15 × 待重做的错题数，最低 0.15。
   - 作用：别的题做对再多，也不能把没清的错题"抵消"掉。例：考点有 8 道错题，其中 3 道毕业了（连着做对 6 次）、5 道没重做。按原规则，最近 3 次全对，这个考点会直接变绿；现在最多 0.25（薄弱）。
   - 已掌握的考点来一道新错题，从 1 掉到 0.85（较好），和现在的规则一样，不会一下掉到"一般"。**【用户定方向，2026-11-12：掉到 0.69 太多】**
2. **变绿（掌握）要同时满足两条**：这个考点下的错题全部毕业，并且最近 3 次结果全对。只满足一条时最高 0.99（较好，黄绿）。
   - 作用：不会出现"星已经绿了，下面还压着没重做的错题"。
3. **验收**：错题已经全部毕业、但最近 3 次还不是全对的考点，下一份卷子抽一道它的相似题来确认。做对就点亮。
   - 作用：只有一道错题的考点，记录是"错、对、对"，再做对一道验收题就是连续 3 次对，可以点亮。
4. **抽查**：已掌握的考点不是不再出题，而是优先级降到最低，每份卷子留少量名额抽查（见 5.3）。抽查做对，保持绿色；做错，掉到 0.85，那道题回到"上次做错"，下一份卷子优先出。**【用户定方向，2026-11-12】**

合起来，一个考点的颜色和它下面错题的清理进度是对得上的：

| 考点下的错题 | 颜色最多到 | 出题优先级 |
|--------------|------------|------------|
| 还有待重做的 | 每多一道，上限低 0.15 | 高 |
| 都至少做对过一次，但还有没毕业的 | 黄绿（较好） | 中 |
| 全部毕业，但最近 3 次还不是全对 | 黄绿（较好） | 低：出一道验收题 |
| 全部毕业，且最近 3 次全对 | 绿（掌握） | 最低：偶尔抽查 |

例：一个考点有 A、B 两道错题。

1. 录入两道错题：0.2，红色。
2. 第一份卷子，A 原题做对、B 原题做错：0.2，红色。
3. 第二份卷子，A 相似题做对（A 毕业）、B 相似题做对：0.5，黄色。
4. 第三份卷子，B 相似题做对（B 毕业）：错题清空，最近 3 次全对，点亮变绿。
5. 之后偶尔抽查。做对保持绿色；做错掉到 0.85，重新来。

补充：

- 手动"直接设为掌握"表示家长认定这个考点已经会了。在这次调整之前录入的错题（按录入时间比，不按卷子日期）从此**视同已毕业**：不压上限、不挡变绿，出卷时只会作为抽查题出现，出的是相似题。之后抽查做错，或者又录入了新错题，按正常规则算。**【Claude 定】**
- 学过但一道错题都没有的考点，照旧停在 0.5（项目 2 的做法）。它没有题可出，这一期也不凭空出题，所以不会变化。
- 这些规则都在 `mastery_model.py` 里改，掌握度是读取时现算的，不用迁移数据。
- **上线那一刻的影响**：现在是绿色、下面却还有没重做错题的考点，会掉回黄绿或更低。出实施计划前用只读查询核对一次，结果给用户看过再上线。要核对的数：会掉出绿色的考点有几颗；题干为空的错题有几道；30 天以前创建、一直没批改的旧练习集有几份（见 5.1）。

计算细节（给实施者）：**【Claude 定】**

- 掌握度仍然是按时间把事件一条条算过去（项目 2 的做法）。新增的上限和变绿条件，**每算一条都按当时的情况判断一次**，不是算完以后统一判断：每处理一条对或错的结果，先加减 0.15，再按"此刻待重做的错题数"压上限；此刻"已录入的错题全部毕业，并且最近 3 次全对"才跳到 1。
- 没跳到 1 的时候，值就是加减出来的数（最高 0.99），不会直接给 0.99。
- 同一份卷子里同一个考点有多道题时，按卷面题号的先后算。上面例子里 A 的题号在 B 前面。
- 掌握度已经是 1 时再做对一次，保持 1。现有代码在"手动设为掌握后做对一次"时会掉到 0.99，一并改掉。
- 手动调整照旧按时间插进去；调整本身不触发"跳到 1"。已点亮的考点被手动"降低一点"后是 0.85，不会被改回 1。
- 数"待重做"和"全部毕业"时，只数能进卷子的题（5.1 的前四条）。进不了卷子的题不压上限、不挡变绿，否则那个考点永远亮不了。

### 4.5 一级、二级考点和错题的关系

**错题只挂二级考点，不挂一级。【用户定，2026-11-12】** 这一条现在已经是这样：数据库有触发器拦着（迁移 0009，报错"只能关联未删除的二级知识点"），录入接口和编辑接口也都校验。这一期不用改，只是把它明确写成规则。

三层之间的关系：

- **错题 → 二级考点**：一道错题有一个主考点，还可以有几个关联考点，都是二级。算 4.4 的"待重做""全部毕业"时，一道题对它挂的每个二级考点都算（和项目 2"主考点和关联考点同样对待"一致）。出卷分名额时只按主考点算，避免一道题占两个考点的名额。
- **二级考点的状态**只来自挂在它上面的错题和这些题的练习结果（4.4）。
- **一级模块的状态只来自它下面的二级考点，不直接看错题**：
  - 掌握度 = 下面已学二级考点的平均值（现有做法，不变）。
  - 变绿 = 下面已学的二级考点全部变绿，并且没有"没学"的二级考点。
  - 这会替换项目 2 第 4.3 节里"至少 N 次、最近 N 次里九成做对"那套条件。那套条件是把下面所有错题的结果合在一起数，等于让一级直接看错题。**【用户定，2026-11-12：同意替换项目 2 的做法】**
- **出卷只在二级上分名额**。一级只用来给卷面分组、在星空上展示。
- 对一级做的手动调整，照旧展开到它下面每个已学的二级（现有做法，不变）。
- 没有挂二级考点的题（五年级旧题、旧的自由文本考点）不参与掌握度，也不进考点卷。

## 5. 出卷规则

### 5.1 哪些题可以进卷子

同时满足：

1. 属于所选学科，并且年级不低于应用的默认年级。**默认不用低年级的错题。【用户定，2026-11-12】** 出卷页上有一个开关"包含低年级的错题"，默认关；打开后这一条只看学科。没填年级的题按当前年级算，可以选。**【开关和"没填年级"的处理是 Claude 定】**
2. 没删除、已通过核对（沿用 `question_scope.COUNTED`）。
3. 至少挂了一个二级考点（没归类的题算不出掌握度，不选）。
4. 题干不为空。
5. 没有毕业（已毕业的题只用于验收和抽查，见 5.2）。
6. 不在别的**还没批改**的错题练习卷里，避免同一道题同时出现在两份卷子上。考点卷和手动组的卷子都算，但只算最近 30 天内创建的；更早的没批改的卷子当作已经放弃，不占着题。**【Claude 定】**

前四条也是 4.4 数"待重做""全部毕业"时用的口径，两边保持一致。其中第 1 条按开关关着的情况算，不随出卷时的开关变：低年级的错题不压考点的上限，也不挡变绿。升年级以后，旧年级没清的错题默认不再出，也不再拖着考点。五年级旧题没有挂二级考点，被第 3 条挡在外面。

英语里只挂词汇、没有语法考点的题不进卷子。

### 5.2 每道题的入选原因

一道题按下面的顺序取第一个符合的原因，这个原因会显示在预览页和答案页上：

| 原因 | 条件 |
|------|------|
| 新错题 | 还没在练习卷里做过，并且错题日期晚于这一科上一份考点卷的出卷时间（从没出过考点卷时，取最近 7 天）。因为出卷频率由家长定，"新"按"上次出卷之后"算，不按固定的一周算 **【Claude 定】** |
| 上次做错 | 最近一次练习结果是错 |
| 旧错题重做 | 还没在练习卷里做过的其他错题 |
| 巩固 | 做对过，但还没毕业 |
| 验收 | 已毕业的题：它的主考点下错题全部毕业，但考点还没点亮（4.4 第 3 条） |
| 抽查 | 已毕业的题：它的主考点已经掌握（4.4 第 4 条） |

没毕业的题都符合前四条之一，都可以选；选多少、先选谁由 5.3 决定。验收和抽查出的都是相似题，每个考点每份卷子最多 1 道。错题日期的取法和项目 2 一样：优先用卷子日期，历史作业用录入时间。

路线图里写的"本周新学章节的题"，在这里落成"新错题"：本周新学的内容，证据就是本周作业里新出现的错题。这一期只从已有的错题出题。**【用户定，2026-11-12】**

### 5.3 题量怎么分给考点

题量 N 是可配置的：家长每次出卷时在出卷页上填写，范围 1–90（和现有练习集的上限一致）；输入框预填上一次用的数，第一次预填 12。**【用户定：题量可配置、手动控制；范围和预填值是 Claude 定】**

名额有两种分法，**出卷时由家长选，默认是均布**：**【用户定，2026-11-12】**

- **均布**（默认）：尽量让每个薄弱考点都出到题。题量少于薄弱考点数时，就是最薄弱的 N 个考点各 1 道。
- **集中**：只练排在最前面的几个考点，每个考点出满 3 道再轮到下一个。

两种分法共用下面的第 1–3 步和第 5 步，只有第 4 步不同。

1. **算每个考点的需要度**（只算有可选题的考点；一道题挂多个考点时按主考点算）：

   | 考点状态 | 需要度 |
   |----------|--------|
   | 薄弱 | 3 |
   | 一般 | 2 |
   | 较好 | 1 |
   | 掌握 | 0 |

   考点下有入选原因是"新错题"的题，需要度再加 1。

2. **给考点排先后**：需要度高的在前；需要度相同时，掌握度数值低的在前；再相同时，待重做的错题多的在前；再相同时，最近一道错题日期新的在前；最后按考点编号，保证每次结果一样。**【Claude 定】**
3. **考点内部按原因挑题**：新错题 → 上次做错 → 旧错题重做 → 巩固（上次练习离现在久的在前）→ 验收。同一原因里，错题日期新的在前。
4. **发名额**，按家长选的分法：
   - **均布**：按第 2 步的先后，一轮一轮地发。第一轮每个考点发 1 道，从排在最前面的考点开始，发满 N 道就停；一轮发完还有名额，再发第二轮（每个考点的第 2 道）、第三轮。
   - **集中**：按第 2 步的先后，一个考点一个考点地发。第一个考点发到 3 道（它的题不够就有几道发几道），再发下一个考点，发满 N 道就停。
   - 两种分法都是每个考点最多 3 道；只剩验收题可出的考点（错题全部毕业、还没点亮）最多 1 道。
   - 所有考点都发到上限还没满 N 道时，放开 3 道的上限，按同样的方式继续发，尽量凑满家长要的题量。可选的题全部用完仍不够，就少出几道，并在预览页说明。**【Claude 定】**
5. 已掌握的考点需要度为 0，不参与分名额，走单独的**抽查名额**：每份卷子默认 1 道，出卷时家长可以改，可以填 0。抽查名额算在题量 N 之内，先留出来，剩下的再按前四步分。抽查最多占题量的一半（向下取整），题量只有 1 道时不抽查。**【Claude 定，写实施计划时补充】**优先抽最久没练过的考点。已掌握的考点不够抽时，名额还给前四步。**【用户定方向：掌握后优先级最低但可以抽查；默认 1 道是 Claude 定】**

例：题量 12，其中抽查 1 道，剩 11 道要分。有 8 个考点可以出题，按第 2 步排好是 A、B、C、D、E、F、G、H，每个考点都有 3 道以上可选的题。

- **均布**：第一轮 A 到 H 各 1 道（8 道），第二轮 A、B、C 各再 1 道（3 道）。结果是 A、B、C 各 2 道，D 到 H 各 1 道，练到 8 个考点。
- **集中**：A 3 道、B 3 道、C 3 道、D 2 道。结果是练到 4 个考点，E 到 H 这次不出。

如果有 30 个考点可以出题，均布就是排在最前面的 11 个考点各 1 道；集中还是前 4 个考点。

这套规则同样写成纯函数（输入：可选的题、各考点掌握度、今天的日期、题量、分法、抽查题数；输出：选中的题和每个考点的备选题），放在 `targeted_model.py`。同样的输入永远得到同样的结果，方便测试。**【Claude 定】**

### 5.4 什么时候出、出几份

- **出卷的频率和题量都由家长手动控制**，系统不规定"每周一份"，也不自动出卷。**【用户定，2026-11-12】**
- 同一科还有**没批改**的考点卷时，再点出卷会先提醒一句"还有一份没批改"，家长可以照样再出一份。按 5.1 的规则，新卷不会选到那份卷子里的题。**【Claude 定】**
- 数学和英语各出各的，不混在一份卷子里（现有练习集就要求同一学科）。每次出卷时由家长选科目。
- 时间用系统现有的北京时间。

### 5.5 和现有练习集的关系

考点卷就是一份练习集（`practice_set`），只是多了"考点卷"标记。这样列表、PDF、批改、掌握度计算都直接沿用。手动组的卷子批改后，结果同样进入 4.1 的复习安排。**【Claude 定】**

现在创建错题练习集有两条路，这一期的处理不同：**【用户定，2026-11-12】**

| 现有入口 | 现在做什么 | 这一期 |
|----------|------------|--------|
| 错题列表顶部的"生成练习"按钮 | 弹窗里选学科、年级、数量，系统按"没复习过 → 正确率低 → 随机"自动选题，全出原题 | **被考点卷替换**。按钮改名"出练习卷"，点了进入出卷页。旧弹窗和旧选题规则从界面上去掉 |
| 错题列表里勾选题目后的"打印原题""打印相似题" | 家长自己挑题组卷 | **保留不动**。这是"我就要练这几道"的场景，考点卷替代不了 |

- 替换而不是并存的理由：两个都是"系统自动选题"，规则却不一样，放在一起家长分不清该点哪个；新规则已经覆盖了旧规则的用途（优先没练过的、做错的）。
- 旧弹窗里的"年级"下拉换成出卷页上的一个开关"包含低年级的错题"，默认关（5.1 第 1 条）。
- 没有挂二级考点的题（五年级旧题）不会被考点卷选到，想练只能走勾选那条路。
- 后端旧接口 `generate-from-questions` 先留着不删，只是界面不再调用。

现在一份练习集要么全是原题、要么全是相似题（`question_type` 是整份卷子的属性）。考点卷需要混排，所以新增类型 `mixed`，原题还是相似题由每道题自己决定。

## 6. 相似题

### 6.1 提示词

在现有提示词（`prompts.py` 的 `_build_prompt`）基础上新写一版，多给模型这些信息：**【路线图】**

- 主考点和它所属的模块（现在已有）；
- 题目有没有图（有图时要求条件全部用文字给出）；
- 要求：考查同一个主考点；题型和难度与原题相近；数字或情境不同；给出答案和三句话以内的解析。

不给模型错因（`question.error_type`），也不给孩子当时的错误答案（`question.wrong_answer`）：相似题只根据错题本身出。路线图原来写的是"加入薄弱考点和孩子的错因"，讨论后一度改为带上错误答案，上线前又改为都不用。**【用户定，2026-11-12】**

返回格式不变（题目、答案、解析），数学题照旧用 KaTeX 校验公式。

### 6.2 保存解析

现在模型返回的解析校验完就丢掉了。`similar_question` 表新增 `explanation` 列存下来，答案页要用。

### 6.3 什么时候复用、什么时候重新生成

- 这道错题有一道**还没被用进任何已批改卷子**、并且带解析的相似题：直接复用，不调模型。
- 否则生成一道新的。
- 这样孩子每次遇到的相似题都不一样，同时一道题在被用掉之前不会重复生成。**【Claude 定】**
- 旧的相似题（没有解析）不再用于考点卷，数据保留。

### 6.4 一步一步生成

一份卷子可能要生成五六道相似题，每道要十几秒。不放在一个请求里做完，改成和整页识别"全部接受"一样的方式：**前端一道一道地请求，页面显示进度**。每个请求最多调用一次模型。**【Claude 定】**

某一道生成失败（模型出错、公式校验不过）时重试一次，仍然失败就**改用原题**，并在预览里标出来。不让一道题卡住整份卷子。

### 6.5 相似题没有人工审核

路线图的原则是"LLM 起草、人审核后才生效"。相似题是一个例外：它不改变统计口径，但答案错了会影响批改。用三层来兜，不要求逐道确认后才能打印：**【用户定，2026-11-12】**

1. 生成后，预览页上可以展开看每道相似题的题目、答案、解析，不满意点"换一道"。
2. 答案页上每道题标明"原题"还是"相似题"，家长批改时知道哪些要多留个心眼。
3. 批改时可以把一道题标成"题目有误"：这道题不计对错、不影响掌握度，这道相似题以后不再复用。

结构变更只追加一个迁移 `cloudflare/migrations/0015_targeted_paper.sql`，只加列，不改不删已有的列，所有新列都有默认值。执行前照例先备份并在副本上演练。

### 9.1 新增的列

| 表 | 列 | 含义 |
|----|----|------|
| `practice_set` | `kind` | `manual`（默认）或 `targeted` |
| `practice_set` | `grading_revision` | 批改版本号，每提交一次加 1，用来发现两人同时修改 |
| `practice_set_question` | `form` | `original` 或 `similar`（这道题印的是原题还是相似题） |
| `practice_set_question` | `reason` | 入选原因：`new`（新错题）/ `wrong`（上次做错）/ `redo`（旧错题重做）/ `consolidate`（巩固）/ `check`（验收）/ `spot`（抽查） |
| `practice_set_question` | `knowledge_point_id` | 这道题是为哪个考点选的（分组排版用） |

旧数据不用回填：旧练习集的 `kind` 是 `manual`，旧的题目行 `form` 为空时按原来的方式判断（整份卷子的 `question_type`）。

### 9.2 批改不重复计数

现在的 `mark-reviewed` 每提交一次，就把每道错题的 `review_count`、`correct_count`、`error_count` 再加一次。改成**按差值计数**：

- 提交时，把每道题的新结果和库里上一次的结果比较，只把变化的部分加减到错题的计数上。
  - 例：上次是"对"，这次改成"错"：正确次数减 1，错误次数加 1，复习次数不变。
  - 例：两次提交完全一样：什么都不变。
- 练习集的"批改次数"和"批改时间"只在**第一次**批改时写入。之后的修改只更新对错、正确率和 `grading_revision`。
  - 这样改批改结果不会改变这次练习在时间线上的位置，掌握度的先后顺序不会乱。项目 2 当时约定的是"重新批改会更新时间"，这里改掉。**【Claude 定】**
- 正确率 = 做对的题数 ÷ 实际批改的题数（"没做"和"题目有误"不算在分母里）。
- 激励系统的星星只在第一次批改时发，修改不再发。
- 提交时带上打开页面时读到的 `grading_revision`，和库里的不一致就返回 409（见 8.3）。电脑端旧弹窗不带这个值，照常提交。

### 9.3 掌握度那边要跟着改的

`starmap.py` 取练习结果的那条 SQL 现在是"`is_correct` 不为空就算"。加了"没做 / 题目有误"以后这两种情况的 `is_correct` 本来就是空，不用改。只需要确认一条：标成"题目有误"时把 `is_correct` 清空。

**掌握度的规则要改**，见 4.4 和 4.5。落到代码上：

- `mastery_model.py`：二级考点加"待重做的错题压上限"和"全部毕业才能变绿"两个条件；一级模块的变绿条件改成"已学的二级全部变绿"。`LEAF_N = 3` 不变。

## 10. 接口

新文件 `cloudflare/src/targeted.py`（路由和取数）+ `targeted_model.py`（纯规则），挂在 `/api/practice-sets/targeted` 下。

| 接口 | 作用 |
|------|------|
| `GET /api/practice-sets/targeted/status` | 待批改卷子的数量（首页"专项练习"那一格和练习中心页头用），以及每科最近一份考点卷的出卷日期和状态（出卷页最上面那行用） |
| `POST /api/practice-sets/targeted/plan` | 传学科、题量、分法（均布 `spread` 或集中 `focus`，不传按均布）、抽查题数和是否包含低年级（不传按不包含），返回系统选好的题（题干、考点、原因、原题还是相似题、是否有图）和每个考点的备选题。**只算不存，不调模型** |
| `POST /api/practice-sets/targeted` | 传最终确定的题目清单，创建考点卷。相似题这时还没生成 |
| `POST /api/practice-sets/targeted/{id}/prepare` | 为一道还没准备好的相似题生成或复用一道，返回还剩几道。前端反复调用直到剩 0 |
| `POST /api/practice-sets/targeted/{id}/reroll` | 传卷子里的一道题，把它的相似题换成新生成的一道；旧的那道作废，以后不再复用。只能在卷子还没批改时用 |
| `POST /api/practice-sets/{id}/generate-pdf` | 现有接口，按考点卷版式生成 PDF |
| `POST /api/practice-sets/{id}/mark-reviewed` | 现有接口，改成按差值计数；新增可选字段：每题的跳过原因、`grading_revision` |
| `GET /api/practice-sets/{id}` | 现有接口，多返回 9.1 的新列和每道题的解析 |

免费计划的考虑：

- `plan` 复用项目 2 的掌握度计算（固定几条 SQL），再加两条取题目和练习结果，SQL 条数不随题目数量增加。
- 每个 `prepare` 请求最多调用一次模型、一次公式校验。
- PDF 沿用现有的"内容没变就不重新生成"的指纹缓存。

## 项目背景

EasyFix 是一个学生错题整理应用，目标是帮孩子走完一条环：**收集错题 → 整理薄弱 → 针对练习 → 看到提升**。整体方向和六个项目的拆分见路线图 `2026-11-10-optimization-roadmap.md`。

实际使用方式（用户确认过）：

- 父母是主要操作者，在手机和电脑上使用；系统部署在公网，父母双方都会参与。
- 节奏按周：每周把作业和考试错题的照片贴给 GPT，由 GPT 识别后写入系统。试过 OCR，效果不好，不再走这条路。
- 练习是纸质的：系统生成 PDF 打印给孩子做，做完由父母导入结果。批改是手机上拍照留存加手动点对错，不做手写识别。
- 孩子本人只用单词默写这一个界面。
- 教材是沪教版。孩子目前六年级，科目为数学和英语。

## 项目 1 要解决什么

现在的断点在"收集"这一环：

- GPT 录题时考点可以随意填，录入后还要人工归类。
- 没有记录孩子当时怎么错的，后面判断错因、出针对性的相似题都缺数据。
- 不知道一道题来自作业、考试还是章节练习，也不知道它属于哪张卷子。
- 章节练习和考试的分数没有地方记。
- 所有数据没有学生维度，以后要支持多个孩子时需要逐表迁移。

做完后的效果：用户照旧贴图给 GPT，但进来的数据直接可用，分数有地方记。它是项目 2（掌握度）、项目 3（组卷）、项目 4（报告）的数据基础。

## 已定的范围

以下是路线图讨论时用户同意的内容：

1. **录入规范和考点目录接口**：GPT 录题前读取该年级的考点清单，只能从清单里选主考点和关联考点；系统写入时校验，选了不存在的考点就拒绝。
2. **每道题多记三样**：来源（作业 / 考试 / 章节练习）、所属批次（哪天哪张卷子）、孩子的错误答案。
3. **每周确认队列**：GPT 录入的题标为"待确认"，父母确认后才计入统计。
4. **测评记录表**：章节练习、单元测、期中期末共用一张表，记类型、关联章节、得分、满分、日期；卷面上的错题可以挂到这条记录下。
5. **多学生预留**：建学生表和默认学生，现有数据归他；学习数据表加学生字段；现有查询暂不加学生过滤；不做登录和切换界面。知识点目录、教材章节等全局共享，不按学生复制。

明确不在本项目里的：教材章节表和进度推断（项目 2）、掌握度计算（项目 2）、组卷和批改流程（项目 3）、报告（项目 4）、语文、多学生界面。

## 待确认的问题

设计前需要用户回答，按重要性排序。

1. **GPT 现在怎么把题目写进系统？** 是调用系统的接口，还是用别的方式直接写数据库？这决定"校验"放在哪里才真正生效。代码里已有 `POST /api/questions/batch`，会把关联标记为 `agent` 来源，鉴权支持 `Bearer ACCESS_TOKEN`；但用户实际走的是不是这条路，没有确认过。数学公式的文档里提到过"Agent 直接写库会绕过接口校验"。
2. **GPT 的录入指令放在哪里？** 是某个 GPT 的自定义指令、一段每次粘贴的提示词，还是别的？录入规范最终要写进那里。
3. **"待确认"的题在确认前怎么处理？** 完全不显示在错题列表里，还是显示但带标记、只是不计入统计？确认时父母需要改哪些字段（考点、错因、题干）？
4. **"批次"怎么定义？** 一次贴图算一批，还是一张卷子算一批？一批里需要记哪些信息（日期、名称、来源类型）？批次和测评记录是同一个东西，还是测评记录是带分数的批次？
5. **孩子的错误答案怎么记？** 只记文字，还是也要保留原图上的作答痕迹？GPT 能从照片里可靠地读出孩子的作答吗，还是需要用户补充？
6. **测评记录要多细？** 只记总分，还是也按模块或题型记失分？分数由谁录入，在哪里录（页面表单，还是也交给 GPT）？
7. **现有的错题要不要补这些新字段？** 目前约 600 道题没有来源、批次和错答。全部留空，还是给一个"历史数据"的默认值？
8. **学生字段加到哪些表？** 路线图说的是"学习数据表"，需要列出清单并确认，例如错题、单词、练习、报告、成就。

## 现有代码里和项目 1 相关的事实

以下是写这份文档时核对过的，实施前仍应再读一遍代码。

- **正式环境是 Cloudflare**：代码在 `cloudflare/src/`，数据库是 D1，文件在 R2。`backend/app/` 是未同步的旧本地版，不要改。
- **错题表 `question` 的现有列**：题干、原图、答案、解析、年级、学期、难度、`error_type`（自由文本，逗号分隔）、`knowledge_point`（主考点名称的投影）、复习计数等。没有来源、批次、错答、学生、确认状态这些列。
- **考点**：两级树（学科 → 一级模块 → 二级考点），题目通过 `question_knowledge_point` 关联，每题恰好一个主考点，关联带 `source`（`manual` / `migration` / `agent`）。六年级 366 题已归类；五年级 206 题仍是旧的自由文本标签。目录接口有 `GET /api/knowledge-points/tree`。
- **录入接口**：`POST /api/questions`（单题）和 `POST /api/questions/batch`（批量）在 `cloudflare/src/questions.py`，写入时已有考点校验和版本守卫。
- **鉴权**：全站共享密码登录，会话里不带身份；另支持 `Bearer ACCESS_TOKEN` 给 Agent 使用。系统分不清是谁在操作。
- **数据库迁移**：追加到 `cloudflare/migrations/`，下一个编号是 `0011`。只加不改，所有表软删除。
- **测试**：没有统一的测试套件。后端沿用独立脚本的做法（内存 SQLite 复现 D1），参考 `cloudflare/scripts/phrase_focus_test.py` 和 `knowledge_invariants_test.py`；前端纯逻辑用 `node --test`。

## 工作方式

项目 0 是这样走的，项目 1 沿用：

1. **确认**：逐个问清"待确认的问题"，一次只问一个。
2. **设计**：写设计文档到 `docs/superpowers/specs/`，先让独立审阅者检查一遍，再交用户确认。文档里要分清哪些是用户定的、哪些是 Claude 替用户定的。
3. **计划**：写实施计划到 `docs/superpowers/plans/`，按任务拆分，每个任务有测试。
4. **实施**：按任务实施并审阅。纯规则写成不依赖数据库的函数，方便测试。
5. **发布**：部署正式环境前必须得到用户明确同意，每次都要问。

约定：

- 用中文交流。用户是编程初学者，说明要直白，少用术语。
- 代码规范：变量小写下划线，函数前写中文文档字符串，复杂逻辑加中文行内注释。
- 保持 Workers 免费计划：统计用 SQL 聚合，不按记录逐条查询。
- 数字由服务端计算，LLM 只负责解释；LLM 起草的内容，凡是影响统计的，人确认后才生效。

## 发布时要注意的环境情况

详见 `docs/cloudflare-migration-status.md` 末尾 2026-11-10 的几条记录。要点：

- 发布文档里说的授权目录 `tmp/cloudflare-config` 和打包好的 Python 依赖在这台机器上不存在。项目 0 用的是系统默认位置的 Wrangler 登录，Wrangler 4.158.0 取自 `D:/code/easyfix-cloudflare-inspect/cloudflare/node_modules`。
- Python 依赖需要用 `uv run pywrangler sync` 按 `pylock.toml` 重新打包，它要求 uv 0.13.4 以上；系统里的 uv 版本不够，项目 0 在 `tmp/uv-new` 单独装了一份。
- 本机代理访问 Cloudflare 接口不稳定，命令要去掉代理环境变量直连。
- 有数据库迁移时：先导出完整备份，在备份副本上演练迁移，再执行，执行后与备份核对。
- 主目录 `D:\code\easyfix` 里的本地 `main` 停在很早的提交，工作区有大量未提交的改动，来源不明，不要动它。远端 `main` 是最新的，项目 0 是从工作树直接推送到远端 `main` 的。
- 工作树曾在一次任务中途被意外清空过，原因没查明。建议勤提交，重要的中间产物不要只放在工作树里。

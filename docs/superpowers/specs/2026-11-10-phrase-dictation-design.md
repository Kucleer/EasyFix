# 词组默写优化设计

日期：2026-11-10
状态：待确认
所属路线图：`2026-11-10-optimization-roadmap.md` 项目 0

## 为什么做

单词默写是孩子本人在电脑和手机上高频使用的功能。现在单词和词组存在同一张 `word` 表里，没有类型区分。默写时页面显示中文，把整条英文拆成字母格，只有空格和符号预填，其余每个字母都要打（`frontend/src/views/Words.vue` 的 `dictationCells`）。

对词组这带来两个问题：

- `look forward to doing sth.` 要打二十多个字母，其中大部分是孩子早就会的词，练习时间花在了非重点上。
- 任何一个字母错都算整条错，系统不知道错在哪个词。

## 目标

1. 词组默写时只空出重点词，其余部分直接显示。
2. 重点词同时包含两类（用户决定两类都要）：
   - **搭配词**：固定搭配里容易记混的介词、副词小品词，如 `be good at` 的 `at`。
   - **生词**：词组里孩子还没掌握的实词，如 `be proud of` 的 `proud`。
3. 不产生假掌握：词组要达到"牢记"，必须通过完整默写。
4. 记录错在哪个词，并让反复写错的词自动成为重点。

## 非目标

- 不改变单词（非词组）的默写方式。
- 不改变"选择中文"和"听力"两种题型。
- 不改变间隔复习的间隔算法（答对间隔翻倍、上限 30 天，答错回到 1 天）。
- 不做例句填空。
- 不做手写或语音输入。
- 不涉及多学生字段，那是项目 1 的范围。

## 反目标

出现下面任何一条，即使功能可用也算失败：

- 孩子只会填介词就被标记为"牢记"。
- LLM 的标注覆盖了父母已确认或手动修改过的重点。
- 已有单词的复习历史、计数、记忆阶段被改动。
- 把 `good`、`take`、`part` 这类早已掌握的基础词当成生词空出来，导致重点默写和完整默写没有区别。

## 约束

- 只改云端和前端：`cloudflare/src/`、`cloudflare/migrations/`、`cloudflare/scripts/`（测试脚本）和 `frontend/src/`。不同步 `backend/app/`。
- 数据库变更追加到 `cloudflare/migrations/`（下一个编号是 0010），不重建表。
- 保持 Workers 免费计划：抽题和提交不能按词逐条查询数据库；LLM 标注按批调用，每批不超过 20 条。
- 软删除规范不变。
- 复习提交的幂等机制（`request_record` 指纹）不变。
- 对错仍由前端判定后提交，这是现有做法，本次不改为服务端重判。

## 设计

### 1. 区分单词和词组

`word` 表新增 `entry_type`，取值 `word` 或 `phrase`，默认 `word`。

- 迁移时回填：`english` 去掉首尾空白后仍含空白字符的记为 `phrase`。
- 新建和批量导入时按同一规则自动判定，父母可以在编辑时手动改。
- 连字符词（如 `ice-cream`）和缩写（如 `a.m.`）不含空白，算单词。

### 2. 重点标注的存储

`word` 表新增两列：

- `focus_spec`：JSON 文本，可为空。
- `focus_status`：`none`（未标注）、`draft`（LLM 起草，未确认）、`confirmed`（父母确认或手动修改过）。

`focus_spec` 结构：

```json
{
  "version": 1,
  "source_english": "be proud of sb.",
  "tokens": [
    {"text": "be", "role": "plain"},
    {"text": "proud", "role": "content", "lemma": "proud", "gloss": "自豪的"},
    {"text": "of", "role": "collocation"},
    {"text": "sb.", "role": "placeholder"}
  ]
}
```

词的切分规则：按空白切分 `english`，每段是一个 token，标点留在所属 token 内。`tokens` 的 `text` 按顺序用单个空格连接后，必须与规范化空白后的 `english` 完全相同，否则拒绝写入。

四种角色：

| 角色 | 含义 | 重点默写时 |
| --- | --- | --- |
| `collocation` | 搭配词 | 总是空出 |
| `content` | 本年级可能是生词的实词 | 未掌握时空出，见第 3 节 |
| `plain` | 基础词（be、a、the、take、good 等） | 显示 |
| `placeholder` | 占位符（sb.、sth.、doing、one's 等） | 任何档位都显示 |

`content` 带 `lemma`（原形，用于对照单词本）和 `gloss`（中文释义，用于"加入单词本"）。

`english` 被修改后，如果与 `source_english` 不一致，`focus_status` 重置为 `none`，`focus_spec` 保留但不再使用，等待重新标注。

**"哪些实词算基础词"由 LLM 在标注时判断**，依据是该条目的年级。这是为了避免反目标第 4 条：单词本里没有 `good`，不代表它是生词。

### 3. 每次默写时重点词如何确定

抽题时由服务端计算，一条词组的重点词是下面三个来源的并集：

1. 所有 `collocation`。
2. `content` 中未掌握的：用 `lemma` 不区分大小写匹配 `word` 表中 `entry_type='word'` 且未删除的条目。匹配到且 `learning_phase` 为"牢记"，视为已掌握，不空；匹配不到或未到"牢记"，空出。
3. 错误驱动：该词组最近 5 次默写记录里，某个 token 错了 2 次及以上，则空出，不论它是什么角色（`placeholder` 除外）。

结果：孩子把 `proud` 单独背到"牢记"后，它自动从 `be proud of` 的重点里退出；某个本来显示的词反复写错，会自动加入。

如果并集为空（例如所有词都已掌握且没有搭配词），该词组本次按档位 3 完整默写：日志记为档位 3，答对可以授予"牢记"，存储的 `dictation_level` 仍按第 4 节规则升一档。

错误驱动只统计带 `token_results` 的默写记录，并且只看当前这份标注生效之后的记录；`english` 修改并重新标注后，旧记录的 token 下标不再可信，不参与计算。

`lemma` 匹配到多个单词条目时，任意一条达到"牢记"即视为已掌握。

实现要求：对一次抽出的全部词组，生词对照和最近记录各用一次批量查询完成。

### 4. 三个默写档位

| 档位 | 名称 | 空出哪些 | 提示 |
| --- | --- | --- | --- |
| 1 | 重点默写 | 第 3 节算出的重点词 | 无 |
| 2 | 提示默写 | 所有非占位符 token | 每个词显示首字母 |
| 3 | 完整默写 | 所有非占位符 token | 无 |

`word` 表新增 `dictation_level`（1 到 3）。

- 单词条目恒为 3，行为与现在一致。
- 未标注（`focus_status='none'`）的词组实际档位恒为 3，行为与现在一致，占位符也照旧需要填写。列里仍保存迁移初值，标注后才开始生效。
- 不含字母的 token 任何档位都显示；只有一个字母的 token 在档位 2 不空出。
- 已标注的词组：默写答对升一档，上限 3；答错降一档，下限 1。只有默写题型会改变档位，选择和听力不改。
- 迁移时的初值：已是"牢记"的词组为 3，其余为 1。

"牢记"的**授予**在现有条件（本次答对、连续答对 3 次及以上、间隔不少于 7 天）之外，对已标注的词组增加一条：**本次是档位 3 的默写**。按现有间隔 1 → 2 → 4 → 8 天的节奏，孩子正常答对时第三次起就在档位 3，不会拖慢进度。

这一条只管授予，不管保持：

- 已经是"牢记"的词组，之后以任何题型或档位答对，都保持"牢记"，不会因为不是档位 3 而被降级。答错时照现有规则处理。
- 还不是"牢记"的已标注词组，通过选择、听力或档位 1、2 的默写答对，间隔照常增长，但阶段不会变成"牢记"。也就是说，已标注的词组只靠选择或听力到不了"牢记"，这是有意的。
- 单词条目和未标注词组的判定与现在完全一致。

开始复习时提供档位选择：自动（默认）、重点、提示、完整。手动选择只影响本次显示，不写回 `dictation_level`；但"牢记"仍只在实际以档位 3 完成时授予。

`draft` 状态的标注可以直接用于默写，不必等父母确认。理由是标注错了最多是空错了词，不会污染计数；父母随时可以改。

### 5. 判对与记录

- 每个空出的 token 单独判定：不区分大小写，其余必须完全一致。
- 整条的 `is_correct` 为所有空都对，间隔复习照此计算，规则不变。
- `word_review_log` 新增两列：`token_results`（JSON，如 `[{"i":1,"ok":false},{"i":2,"ok":true}]`，`i` 是 token 下标，只含本次空出的 token）和 `dictation_level`。
- 单词条目和未标注词组这两列为空。
- 答错时页面标出具体错的词，并显示完整正确答案。

### 6. 接口变化

**`POST /api/words/review/start`**

- 新增参数 `entry_type`（`word` / `phrase`，不传为混合）和 `dictation_level`（1 到 3，不传为自动）。
- 每道题新增字段：`entry_type`、`dictation_level`、`tokens`（数组，每项含 `text`、`blank`、`hint`；`hint` 仅档位 2 的空出词有，值为首字母）。单词条目和未标注词组不返回 `tokens`，前端沿用现有字母格逻辑。
- 抽题优先级不变。

**`POST /api/words/review/submit`**

- 每条结果可带 `token_results` 和 `dictation_level`，服务端校验形状和范围后写入日志，并更新 `word.dictation_level` 和"牢记"判定。
- 幂等指纹照旧对整个请求体计算。
- 前端上报的 `dictation_level` 直接采信，与对错由前端判定的做法一致。
- 接受 `review_type=3`（听力）。现有代码只接受 1 和 2（`review.py` 提交校验），而前端听力题型提交的是 3，按代码看听力场次目前无法提交。本次顺带修复：听力按现有间隔规则计入，不改变档位，对已标注词组不授予"牢记"。
- 删除练习记录不回滚 `dictation_level`，与现有对间隔和阶段的处理一致。

**`POST /api/words/focus/annotate`**（新增）

- 入参：词组 id 列表，最多 20 条。
- 对 `focus_status` 不是 `confirmed` 的条目调用一次 LLM（复用 `settings.generate_json`），写入 `focus_spec` 并置为 `draft`。`confirmed` 的条目跳过。
- 服务端校验每条返回：token 序列与 `english` 一致、角色合法、`content` 带 `lemma`。校验不通过的条目保持 `none`，在响应里逐条说明原因，不影响同批其他条目。
- 响应附带 `missing_lemmas`：标为 `content` 但单词本里没有的原形及其中文释义。

**`PUT /api/words/{id}` 和批量导入**

- 接受 `entry_type` 和 `focus_spec`。带 `focus_spec` 写入时按同样规则校验，通过后置为 `confirmed`。这也是 GPT 录入时直接附带标注的入口。
- 普通编辑（改中文、音标、年级等）不带 `focus_spec`，不会把 `draft` 变成 `confirmed`。
- 批量导入时某条的 `focus_spec` 校验不通过：该词照常导入但不带标注，并在结果里说明原因。
- 条目没有年级时，标注按应用默认年级判断基础词。

**`GET /api/words`**

- 新增筛选 `entry_type` 和 `focus_status`，返回这两个字段及 `focus_spec`。

**`GET /api/words/stats/summary`**

- 新增 `by_type`：单词和词组各自的数量与正确率。

### 7. 标注 prompt

放入 `cloudflare/src/prompts.py`。输入为一批词组的 id、英文、中文、年级；输出为每条的 token 角色。prompt 需要明确：

- 不得增删、改写或重新切分 token，只给每个 token 定角色。
- 搭配词的范围：介词、副词小品词、不定式的 to、固定搭配里容易与近义搭配混淆的词。
- 基础词的判断依据是年级；拿不准时标为 `content`（宁可多练）。
- 占位符清单：sb.、sth.、sp.、doing、do、one's、oneself 及其变体。
- `content` 必须给原形和中文释义。
- 只返回 JSON。

prompt 的具体措辞留给实现者，按上述要求编写并用下面的样例验证。

验证样例（期望的重点默写显示）：

| 词组 | 期望显示 |
| --- | --- |
| be good at | `be good __` |
| be proud of（proud 未掌握） | `be _____ __` |
| be proud of（proud 已牢记） | `be proud __` |
| look forward to doing sth. | `look _______ __ doing sth.` |
| take part in | `take part __` |
| help sb. with sth. | `help sb. ____ sth.` |

### 8. 前端

**默写页（孩子用）**

- 把字母格输入从 `Words.vue` 抽成独立组件，输入为 token 列表或整条英文。显示的 token 以普通文字呈现，空出的 token 呈现为字母格；档位 2 的首字母预填且不可改。
- 键盘输入、退格、回车提交的行为与现在一致，光标只在可填的格子间移动。
- 提示文字从"N 个字母"改为按空出的词说明，如"2 个词"。
- 开始复习的设置里增加"范围：全部 / 只练单词 / 只练词组"和"词组档位：自动 / 重点 / 提示 / 完整"。
- 答错时标红具体错的词。
- 发音：已标注词组在档位 1、2 作答前不自动播放，喇叭按钮禁用；提交后自动播放一遍整条英文作为巩固。档位 3、单词条目、未标注词组保持现状（进入题目时自动播放两遍）。原因是先听到整条再填搭配词，就成了听写而不是回忆。
- 手机上保持现有的隐藏输入框唤起键盘的做法。

**单词本（父母用）**

- 列表显示类型标记，可按类型和标注状态筛选。
- "标注词组重点"按钮：对未标注的词组分批调用标注接口，显示进度和失败条目。
- 词组详情里的重点编辑：点击某个词在四种角色间切换，保存后置为 `confirmed`。
- 标注完成后列出 `missing_lemmas`，可勾选后一键加入单词本（年级和学期沿用该词组的）。

**打印默写**

- `cloudflare/src/media.py` 的默写试卷：词组按所选档位输出，如"擅长　be good ____"。单词保持"中文（N 个字母）"。打印弹窗增加档位选择，默认重点。

**统计**

- 单词页的概览把单词和词组的数量、正确率分开显示。其余统计页不动，留给项目 5。

### 10. 测试

项目没有测试套件，但 `cloudflare/scripts/` 下已有 `knowledge_*_test.py` 这样的独立测试脚本。本次把重点计算、档位升降、`focus_spec` 校验、token 切分写成不依赖数据库的纯函数，放在独立模块里，并按同样方式配一份测试脚本，至少覆盖第 7 节的验证样例和下列情况：

- `english` 修改后标注失效。
- 重点并集为空时退回完整默写。
- 错误驱动把非重点词加入重点，占位符不会被加入。
- 手动选低档位答对不授予"牢记"。
- 单词条目和未标注词组的抽题、提交结果与改动前一致。

## 决策记录

**用户决定的**

- 词组默写只显示部分内容，让孩子默重点。
- 重点同时包含搭配词和词组里的生词。
- 这个项目排在所有其他项目之前。
- 重点默写和提示默写时，答完再播放发音。

**设计者提出、用户未反对的**

- 三档递进，"牢记"必须通过完整默写。
- 按词记录对错，反复写错的词自动成为重点。
- 单词和词组的统计、抽题范围分开。
- 词组里的生词提示加入单词本。

**设计者自行决定的**

- 用 `word` 表加列的方式实现，不新建词组表。
- 基础词由 LLM 按年级判断，而不是只看单词本里有没有。
- 生词是否已掌握以单词本条目达到"牢记"为准。
- 错误驱动的阈值：最近 5 次默写中错 2 次。
- 档位规则：答对升一档、答错降一档；手动选档不写回。
- `draft` 标注可直接用于默写。
- 占位符在已标注词组的所有档位都显示。
- 迁移时"牢记"的词组初值为档位 3，其余为 1。
- 对错继续由前端判定。
- 把字母格输入抽成独立组件。
- "牢记"的新条件只管授予不管保持；已标注词组只靠选择或听力到不了"牢记"。
- 重点为空时本次按档位 3 计。
- 顺带修复听力题型提交被拒的问题。

- 档位 1、2 作答前喇叭按钮一并禁用（用户只决定了不自动播放，禁用按钮是设计者的延伸）。

## 上线后的调整（2026-11-10，用户决定）

原设计规定未标注的词组一律按完整默写。上线试用后改为：

- **手动选"提示"档对所有词组生效**，未标注的词组也给每个词首字母；常见占位符（sb.、sth.、one's、doing sth. 等）直接显示。打印默写的"提示"档同理。
- **"自动"模式下未标注的词组走 提示 → 完整 两级**：存储档位低于 3 时带首字母默写，答对升到完整默写；完整默写答错退回提示；提示档答错保持不变（初值 1 保留，标注后仍从"重点"档开始）。只有默写题型会改变档位。
- **以低于完整默写的档位答对不授予"牢记"**，未标注词组也适用。"牢记"始终需要一次完整默写答对。
- **不限类型的混合抽题按 60% 单词 + 40% 词组**，各自仍按原优先级抽取，一方不足时由另一方补足，顺序打乱。只练单词、只练词组或指定词条时不套用比例。
- 手动选"重点"或"完整"时，未标注词组仍按原样完整默写。

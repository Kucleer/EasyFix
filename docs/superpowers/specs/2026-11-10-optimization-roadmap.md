# EasyFix 优化路线图

日期：2026-11-10
状态：已确认；项目 0 已上线（2026-11-10），下一步是项目 1，启动文档见 `2026-11-10-project1-kickoff.md`

这份文档记录下一轮优化的方向、项目拆分和顺序。每个项目开工前会单独写设计文档和实施计划，本文不包含实现细节。

## 目标

帮助学生走完一条环：**收集错题 → 整理薄弱 → 针对练习 → 看到提升**。所有项目都以"让这条环更顺、更准"为判断标准。

## 实际使用方式（用户确认）

- **父母是主要操作者**，在手机和电脑上使用；系统部署在公网，父母双方都会参与。
- **节奏按周**：每周把作业和考试错题的照片贴给 GPT，由 GPT 识别后直接写库。之前试过 OCR，效果不好，不再走这条路。
- **练习是纸质的**：系统生成 PDF，打印给孩子做，做完由父母导入结果。
- **批改方式**：手机上拍照留存做完的练习卷，然后手动点对错。不做手写识别批改，精度不够。
- **孩子本人会用的界面只有单词默写**，在电脑或手机上进行，是高频场景。
- **教材**：沪教版。

## 现状要点

- 正式环境是 Cloudflare（`cloudflare/src/` + D1 / R2），`backend/app/` 是未同步的旧本地版。后续只改云端和前端。
- 知识点已有"学科 → 一级模块 → 二级考点"两级树和题目关联表。六年级 366 题已逐题归类（18 模块、75 考点）；五年级 206 题仍是旧的自由文本标签。
- 目录不是按教材整理的：没有教材版本和章节字段，考点之间没有先修关系。
- 没有掌握度指标，只有模块的题数占比、复习覆盖率、练习正确率。
- 自动组卷只按"未复习 → 低正确率 → 随机"选题，不看知识点；错题没有到期复习安排。
- 学习报告的原则（数字由服务端写，LLM 只写文字）是对的，但送给 LLM 的维度少，报告页没有图表，没有趋势和上期对比。
- 数据缺口：首页错题正确率曲线的数据始终为空；阅读只存总正确率；练习时长未使用；没有考试成绩表。
- 全站在共享密码登录之后，会话不带身份，分不清是谁在操作。
- 单词和词组存在同一张表里，没有类型区分；默写时词组要整条逐字母填。

## 贯穿所有项目的原则

1. **知识点是主体，章节是索引**。题目、掌握度、出题、报告都挂在知识点上；教材章节只回答"这个知识点在课本哪里、学到了没有"。
2. **数字由服务端计算，LLM 只负责解释**。沿用现有报告 `schema_version=2` 的做法。
3. **LLM 起草、人审核后才生效**。知识点归类、章节映射这类会影响统计和掌握度的内容按这个流程。词组重点标注例外：草稿可直接用于默写，因为标错只影响空哪个词，不污染计数，父母随时可改。
4. **不改变贴图给 GPT 的录入习惯**，改进放在录入规范和接口校验上。
5. **为多学生预留**：新建的表从第一天起带学生字段；知识点目录、教材章节等全局共享，不按学生复制。
6. **保持 Workers 免费计划**：统计用 SQL 聚合，避免逐记录查询和重复 LLM 调用。
7. **所有表软删除**，沿用现有规范。

## 项目与顺序

| 顺序 | 项目 | 做完后能得到 |
| --- | --- | --- |
| 0 | 词组默写优化 | 词组只默重点词，逐步过渡到完整默写 |
| 1 | 录入规范与测评记录 | 进来的数据直接可用，章节练习和考试分数有地方记 |
| 2 | 教材章节与掌握度 | 系统能说出哪些考点薄弱、哪些还没学 |
| 3 | 每周练习卷与手机批改 | 每周一键出卷，批改几分钟完成 |
| 4 | 周报与学情报告 | 每周一份有图表、有结论的报告 |
| 5 | 首页工作台与界面整合 | 界面跟着这条环走，不再重复堆数字 |

### 项目 0：词组默写优化

默写是孩子每天都在用的功能，用户要求放在最前面。它不依赖其他项目。

- 区分单词和词组。
- 给词组标注重点词，包含两类：固定搭配里的介词等，以及词组里孩子还没掌握的生词。
- 默写分三档：只默重点词 → 首字母提示 → 完整默写，随记忆阶段递进。
- 按词记录对错，反复写错的词自动成为重点。

设计文档：`2026-11-10-phrase-dictation-design.md`

### 项目 1：录入规范与测评记录（收集）

- 给 GPT 的录入规范和考点目录接口；写入时校验考点必须来自目录。
- 每道题多记：来源（作业 / 考试 / 章节练习）、所属批次、孩子的错误答案。
- GPT 录入的题进入"待确认"队列，父母确认后才计入统计。
- 新增测评记录表：章节练习、单元测、期中期末共用，含类型、关联章节、得分、满分、日期；卷面上的错题可以挂到这条记录下。
- 学生表和学生字段预留：建一个默认学生，现有数据归他；现有查询暂不加学生过滤。

### 项目 2：教材章节与掌握度（整理）

- 沪教版教材章节表，以及"章节 ↔ 考点"映射。保留现有两级考点树不动。
- 学习进度自动推断：取最近录入的错题和章节练习所涉及的最靠后章节，只前进不后退，首页显示并可一键改正。
- 未学到的考点显示为"未学"，不算薄弱，不进入出题范围；没有对应章节的考点视为已学。
- 考点掌握度读取时计算，分四档：薄弱 / 待巩固 / 已掌握 / 数据不足。样本太少时不给假分数。
- 薄弱考点清单。

前提：需要用户提供数学和英语在用课本的目录页照片。章节目录不凭记忆编写。

### 项目 3：每周练习卷与手机批改（练习）

- 自动组卷：到期该复习的旧错题、薄弱考点的相似题、本周新学章节的题，按掌握度分配题量。
- 练习卷按考点分组排版，答案和解析单独成页，每题印短编号。
- 相似题 prompt 加入薄弱考点和孩子的错因。
- 错题加上到期复习安排，复用单词的间隔逻辑。
- 手机批改：拍照留存卷面，默认全对、只点做错的题，可选填错因；提交后更新掌握度。
- 一份卷子被一人提交后，另一人看到的是已批改结果，可修改但不重复计数。
- 首页先加"待批改""本周练习卷"两个入口。

### 项目 4：周报与学情报告（提升）

- 服务端计算完整的事实包：本期与上期对比、薄弱考点清单、错误类型 × 模块交叉表、练习趋势、单词、阅读、测评记录。
- LLM 输出改为"洞察块"：每块指向一张图或一个模块，写结论、原因、行动，另加下周计划。
- 报告页用 ECharts 渲染，每张图配 LLM 解读。
- 重写报告 prompt，并把现有两份（`prompts.py` 和 `analytics.py` 内联的那份）合并为一处。
- 报告读者是父母，语气偏分析，不写鼓励式套话。周报随每周循环生成，月报和学期报告做汇总。
- 补上数据缺口：错题正确率曲线、阅读按题保存对错。

### 项目 5：首页工作台与界面整合

- 首页改为父母的每周工作台：待确认题数、本周练习卷状态、待批改卷子、本周考点变化。
- "知识点分析"和"学习报告"合并为一个学情区，筛选条件统一为年级 / 学科 / 时间。
- 共用统计卡、图表卡组件和统一的图表主题；去掉首页未使用的 `echarts-gl`。
- 孩子用的默写页单独对待：简单、字大、干扰少。

放在最后是因为前面几个项目都会新增页面和图表，先整版式会返工。

## 暂不做

- 考点先修关系与知识图谱：放在项目 2 之后单独加。
- 五年级 206 题的归类：需要时按六年级同样的流程做。
- 语文：等数学和英语这条环跑通后，先从字词和古诗文默写切入，复用单词本机制。
- 多学生的账号和切换界面：只预留数据结构。
- 成就和奖励：目前是半成品，后期细化。
- 暗色模式；拆分两千行的大页面（只在改到时顺手拆）。

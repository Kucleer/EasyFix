# 项目 1 设计：录入规范与卷子记录

日期：2026-11-10
状态：已确认（2026-11-10），实施计划见 `docs/superpowers/plans/2026-11-10-intake-and-papers.md`；实施中的调整见第 16 节
相关文档：`2026-11-10-optimization-roadmap.md`（路线图）、`2026-11-10-project1-kickoff.md`（启动文档）

文中每条决定都标了来源：**【用户定】** 是用户在对话中明确说的；**【Claude 定】** 是 Claude 替用户做的选择，用户审阅时可以改。

## 1. 为什么做

EasyFix 要帮孩子走完"收集错题 → 整理薄弱 → 针对练习 → 看到提升"这条环。现在卡在第一步"收集"：

- 录题没有固定的路。用户把卷子照片贴给 Claude 或 Codex，说一句"录入错题"。搬到 Cloudflare 之前，它们每次临时写一个脚本直接往数据库里插数据，系统接口里的考点校验从来没起过作用。搬家之后旧数据库已冻结，目前没有可用的录入办法。
- 录进来的数据出过三类问题（用户原话）：做对的题被当成错题录进来（老师批改过的卷子）；错题和图片对不上；内容识别错（少，但难检查）。
- 不知道一道题来自哪份卷子、孩子当时写了什么。
- 考试分数没有地方记。
- 数据没有"属于哪个孩子"的概念。

"图片对不上"在代码里有直接原因：批量录题接口把一批的所有照片整体挂到每道题上，每道题的"原图"固定取第一张（`cloudflare/src/questions.py` 第 355 行）。

做完之后：用户照旧贴图、说一句话；进来的题考点一定在目录里、原图一定对得上、带着孩子的错误答案和所属卷子；拿不准的题单独放着等人看；考试分数有地方记。这是项目 2（掌握度）、项目 3（组卷）、项目 4（报告）的数据基础。

## 2. 目标、不做的事、要避免的结果

### 目标

1. 让 Claude 或 Codex 录题只有一条路：它们看图识别，通过一个固定的小工具提交给系统接口，接口负责校验。网页上的手工录入页（`Upload.vue`）是父母自己打字录单题用的，保持原样，见 8.3。
2. 每道题记下：来自哪份卷子、哪一页、题号、孩子的错误答案、判断它是错题的依据。
3. 没问题的题直接入库并计入统计；有疑问的题标为"待核对"，在父母处理之前不计入统计、不进练习卷。
4. 每一份卷子或作业是一条记录，考试可以记得分和满分。
5. 建好"用户 → 学生"两层结构，现有数据全部归默认学生。

### 不做（留给后面的项目或明确不要）

- 教材章节表、章节与考点的对应、学习进度、掌握度（项目 2）。卷子记录这次不带"关联章节"，项目 2 建章节表时再加这一列。
- 组卷和批改流程（项目 3）、报告（项目 4）、首页工作台改版（项目 5）。
- 登录账号、学生切换界面、按学生过滤的查询。
- OCR。系统里已经没有 OCR，这次也不接回来。
- 裁剪图片。每道题挂的是它所在那一页的整张照片。
- 通用的"待办中心"。这次只有"待核对的题"一个入口。
- 批量修复旧题的原图错位。发现哪道不对，单独改那一道。
- 五年级 206 道旧题的考点归类。
- 改造旧的 `POST /api/questions/batch` 接口。它保持原样，只是不再用于录题。
- 往已有的卷子记录里追加照片和题目、合并两条卷子记录。同一份卷子分两次贴图会成为两条记录，出现时删掉多余的那条或改个名字。**【用户定：这种情况很少，先不做】**

### 要避免的结果（即使功能做出来了也算失败）

- 待核对队列变成必经关卡，题堆在里面，统计拿不到新数据。大多数题必须能直接入库。
- 录题比现在更麻烦。提交前最多被问一句话，而且可以跳过。
- 做对的题混进统计和练习卷。
- 录题时又绕过接口直接写数据库。

## 4. 整体做法

```
用户贴照片 + "录入错题"
        │
        ▼
Claude / Codex 按《录入规范》看图识别
        │  先取考点清单（接口）
        │  问用户一句：哪份卷子？考试多少分？（可跳过）
        ▼
录入小工具：上传照片 → 试提交（只检查不写入）→ 改错 → 正式提交
        │
        ▼
系统接口校验 ──不合格──▶ 整份退回，说明每道题的问题
        │合格
        ▼
一条"卷子记录" + 若干道题
        ├─ 没问题的题：直接计入统计
        └─ 有疑问的题：待核对 ──父母处理──▶ 通过 / 改后通过 / 移除
```

分成五块：数据库、录入接口、录入规范和小工具、核对与卷子页面、统计口径。

## 5. 数据库（迁移 `0011`）

只加表、加列、加索引，不改不删现有的列。所有新表带 `deleted`。**【Claude 定】** 下面的表名、列名都是 Claude 定的。

### 5.1 用户表 `app_user` 和学生表 `student`

- `app_user`：`id`、`name`、`deleted`、`created_at`。预置一行：`id=1`，名称"默认用户"。
- `student`：`id`、`user_id`、`name`、`deleted`、`created_at`、`updated_at`。预置一行：`id=1`，归属用户 1，名称"默认学生"。

表名用 `app_user` 而不是 `user`，因为 `user` 在部分数据库里是保留字。学生表这次不带年级和教材版本：年级沿用现有的应用默认年级设置，教材版本是按学科分的，随项目 2 的章节表一起设计。

### 5.2 学生字段 `student_id`

规则：**除了系统自带的目录和后台表，其余数据都属于学生；附属表跟着它的主表走，不单独加。**

| 分类 | 表 |
| --- | --- |
| 加 `student_id INTEGER NOT NULL DEFAULT 1` | `question`、`error_book`、`paper`（新表）、`word`、`word_review`、`word_review_session`、`practice_set`、`learning_report`、`reading_passage`、`tag`、`reward`、`redemption`、`star_balance`、`star_record`、`star_action`、`achievement`、`achievement_progress` |
| 不加，跟着主表走 | `question_knowledge_point`、`question_tag`、`similar_question`、`practice_set_question`、`word_tag`、`word_review_log`、`reading_question`、`achievement_config` |
| 不加，全系统共用 | `subject`、`knowledge_point`、`kp_error_type`、`error_type`、`knowledge_assert`、`write_guard`、`runtime_config`、`request_record`、`operation_log` |

说明：

- 现有的读取和写入代码都不改。旧代码插入新行时不写这一列，数据库自动填 1。
- `star_balance`、`star_record`、`achievement_progress`、`redemption` 四张表里已有一列 `user_id`（默认 1），是历史遗留，实际含义是"这个孩子"。这次不动它，只是并排加上 `student_id`。以后真正做多学生时再统一。
- 新写的代码（录入接口、卷子接口）通过一个函数取"当前学生"，目前固定返回 1。以后做多学生时只改这一处。
- 上表中有几张表的列清单是从旧版模型推出来的，不是从正式库读的。**实施时必须先用正式库的导出核对这些表确实存在、且没有同名列**，再定稿迁移。

### 5.3 卷子记录表 `paper`

一份卷子或一次作业是一条记录。批次和测评记录合成这一张表。**【Claude 定，用户已认可合并】**

| 列 | 含义 |
| --- | --- |
| `id` | 主键 |
| `student_id` | 学生，默认 1 |
| `subject_id` | 学科，必填 |
| `name` | 名称，必填 |
| `paper_type` | 类型：`homework` 作业 / `chapter_practice` 章节练习 / `exam` 考试 |
| `exam_kind` | 仅考试有：`unit` 单元测 / `midterm` 期中 / `final` 期末 / `other` 其他 |
| `paper_date` | 日期，`YYYY-MM-DD` |
| `grade`、`semester` | 年级、学期，可空 |
| `score`、`full_score` | 得分、满分，可空；要么都填要么都不填 |
| `images` | 这份卷子的照片，JSON 数组，按页顺序存图片的存储路径 |
| `notes` | 备注，可空 |
| `source` | 这条记录怎么来的：`agent` 录题时建的 / `manual` 页面上手工建的 / `history` 迁移时为旧题建的 |
| `deleted`、`created_at`、`updated_at` | 软删除和时间 |

- 不按大题或模块记失分。每个模块丢了多少分以后从挂在卷子下的错题反推。**【Claude 定】**
- 分数对三种类型都可填可不填，页面上只在类型是考试时提示填写。**【Claude 定】**
- 考试的四个细分是 Claude 定的。

### 5.4 错题表 `question` 新增的列

| 列 | 含义 |
| --- | --- |
| `student_id` | 学生，默认 1 |
| `paper_id` | 所属卷子记录，可空 |
| `paper_page` | 来自这份卷子的第几张照片，从 1 开始，可空 |
| `question_no` | 卷面上的题号，文字，如"二、5"，可空 |
| `wrong_answer` | 孩子当时写的答案，文字，可空 |
| `wrong_evidence` | 判断它是错题的依据，文字，如"老师打叉""有红笔订正"，可空 |
| `review_status` | `approved` 已通过（默认）/ `pending` 待核对 / `rejected` 已移除 |
| `review_reasons` | 待核对的原因代码，JSON 数组 |
| `review_note` | Claude 或 Codex 写的疑问说明，文字 |
| `reviewed_at` | 父母处理的时间 |

- 新题录入时，`original_image` 填它所在那一页的照片，`original_images` 填只含这一张的数组。这样现有的错题列表和详情不用改就能显示对的图。
- 题号是 Claude 加的：核对时要在整页照片上找到这道题，有题号才找得快。**【Claude 定】**
- "移除"的做法是软删除（`deleted=1`）并把 `review_status` 记为 `rejected`，留下痕迹。

待核对的原因代码：

| 代码 | 含义 |
| --- | --- |
| `wrong_unclear` | 不确定这题是否做错了 |
| `text_unclear` | 照片模糊、缺字或被裁切，题干或答案拿不准 |
| `kp_unsure` | 目录里找不到合适的考点 |
| `other` | 其他，说明写在 `review_note` 里 |

### 5.5 旧题的处理

- 旧题的 `review_status` 都是 `approved`，统计和组卷照常使用。
- 按"学科 + 年级 + 学期"给旧题各建一条卷子记录，名称如"六年级上 数学 历史作业"，类型为作业，`source` 为 `history`，不带分数和照片，日期取这组题里最早的录入日期。把旧题的 `paper_id` 指过去。年级或学期为空的旧题归到"数学 历史作业（年级未填）"这样的记录里。**【用户定：旧题当作业；按学科年级学期分组是 Claude 定】**
- 旧题的页码、题号、错误答案、依据留空。原图保持现状。
- 已软删除的旧题也一并回填，保持一致。

### 5.6 索引

- `question(review_status)`，只索引未删除且待核对的行。
- `question(paper_id)`，只索引未删除的行。
- `paper(student_id, paper_date)`，只索引未删除的行。

## 6. 录入接口

新模块 `cloudflare/src/intake.py`（接口）和 `cloudflare/src/intake_model.py`（纯规则函数，不碰数据库，方便测试）。鉴权沿用现有的 `Bearer ACCESS_TOKEN`。

### 6.1 取录入资料：`GET /api/intake/guide`

参数：`subject_id`（必填）、`grade`、`semester`（可选，不传时用应用默认年级学期）。

一次返回录题需要的全部资料：

- `spec_version`：录入规范的版本号，一个整数。
- 学科列表、应用默认年级和学期。
- 该学科该年级的考点两级清单（每个考点的编号、名称、所属模块）。复用现有考点树的筛选逻辑：没有标年级的考点对所有年级可见。
- 该学科可用的错因类型清单。
- 卷子类型、考试细分、待核对原因这几组可选值。

### 6.2 提交一份卷子：`POST /api/intake/papers`

请求内容：

```json
{
  "spec_version": 1,
  "request_id": "客户端生成的唯一编号",
  "paper": {
    "subject_id": 1, "grade": 6, "semester": 1,
    "name": "第三章单元测试", "paper_type": "exam", "exam_kind": "unit",
    "paper_date": "2026-11-08", "score": 85, "full_score": 100,
    "images": ["2026/11/ab12cd34_p1.jpg", "2026/11/ef56ab78_p2.jpg"]
  },
  "questions": [
    {
      "page": 1, "question_no": "二、5",
      "parsed_question": "...", "answer": "...", "analysis": "...",
      "wrong_answer": "...", "wrong_evidence": "老师打叉",
      "difficulty": 3, "error_type": "计算错误",
      "knowledge_point_ids": [12, 15], "primary_knowledge_point_id": 12,
      "needs_review": false, "review_reasons": [], "review_note": ""
    }
  ]
}
```

**整份通过或整份退回。【Claude 定】** 只要有一道题不合格，整份都不写入，返回 422 和问题清单（`errors: [{index, detail}]`，`index` 是题目在请求里的序号）。Claude 或 Codex 改好后重新提交。理由：现有批量接口是"合格的先入库、不合格的报错"，重交时容易重复，一份卷子也会被拆成两半。

**试提交。** 另有一个接口 `POST /api/intake/papers/check`，请求内容相同，只做全部检查、不写入，返回同样的结果结构。小工具正式提交前先走一遍试提交。现有中间件会在每次成功的写请求后刷新缓存版本并记一条操作日志，试提交要像 `/api/stats/analysis/llm` 那样排除在外。

**防重复。** `request_id` 记在现有的 `request_record` 表里。同一个编号再次提交时不重复写入，直接返回第一次的结果。

**版本检查。** `spec_version` 和服务端不一致时拒绝，提示更新录入规范。防止用户电脑上装的是旧规范。

校验规则（写成 `intake_model.py` 里的纯函数）：

卷子部分

- 学科必须存在。年级 1–12，学期 1–2。
- `paper_type` 不传时默认 `homework`。`exam_kind` 只在考试时有效，考试不传时默认 `other`。
- `paper_date` 不传时默认今天（北京时间），不能是未来的日期。
- `name` 不传或为空时，默认"学科名 + 习题 + 日期"，如"数学习题 2026-11-10"。前面加学科是 Claude 加的，避免同一天两个学科重名。**【用户定：习题 + 日期】**
- `score` 和 `full_score` 要么都有要么都没有；都不小于 0；得分不大于满分。
- `images` 是图片存储路径的数组，可以为空；每一项必须是系统上传接口返回过的那种路径格式。
- 一份最多 100 道题，至少 1 道。只想记一个分数、没有错题的考试，在页面上手工新增，不走这个接口。

题目部分

- `parsed_question` 必填。
- 卷子有照片时 `page` 必填，且在 1 到照片张数之间；卷子没有照片时 `page` 必须为空。
- `difficulty` 1–5，默认 3。
- `error_type`：逗号分隔的每一项都必须在该学科的错因类型清单里（清单为空时不校验）。**【Claude 定】** 现在这个字段是随意填的文字，这次顺手收紧。实施时先核对正式库里的清单和现有用法是否对得上，对不上就先补清单再开启校验。
- 考点：编号必须是目录里该学科的二级考点，复用现有的 `resolve_many` 校验。不接受用文字名称代替编号。
- 数学题的题干、答案、解析要通过现有的公式校验（`validate_math`）。整份卷子的文字一次送检，只调用一次渲染服务。现有校验器遇到第一个错就停，返回一句不带题号的说明，这次不改它：公式有错时整份退回，`errors` 里放一条不带 `index` 的记录，说明文字照搬校验器的原话。**【Claude 定】** 不为此改动 PDF 渲染服务。
- `review_reasons` 里的每一项必须是 5.4 列出的代码。

**直接入库还是待核对**（纯函数，输入一道题，输出状态和原因）：

- 满足下面任一条就是待核对：
  - 提交方把 `needs_review` 标为真（此时 `review_reasons` 不能为空）；
  - `wrong_evidence` 为空，系统自动补上原因 `wrong_unclear`；
  - 没有主考点，系统自动补上原因 `kp_unsure`。例外：这个学科这个年级的考点目录是空的（比如升了年级、目录还没建），这时没有考点不算待核对，题目直接入库为未分类，否则整份卷子都会掉进待核对。**【Claude 定，写计划时补充】**
- 其余的直接入库，状态为已通过。
- `wrong_answer` 为空不影响：字迹看不清但老师的批改能说明确实错了，照样直接入库。**【Claude 定，用户未反对】**

写入：卷子记录、所有题目、题目与考点的关联（来源记为 `agent`）在同一个事务里完成，沿用现有的写入守卫（`ensure_guard_rows`、`guard_statement`、`structure_statement`）。缓存失效和操作日志由现有中间件自动处理。

返回：卷子记录、入库的题目、总数、直接入库的数量、待核对的数量。

### 6.3 照片上传

沿用现有的 `POST /api/upload/batch-simple`（一次最多 10 张，每张不超过 10MB，只收 jpg / png / webp）。小工具按页顺序上传，超过 10 张时分几次传，把返回的路径按顺序填进 `paper.images`。

### 6.4 核对接口

- `GET /api/questions` 增加两个筛选参数：`review_status` 和 `paper_id`。返回的每道题带上新列和所属卷子的名称。不传 `review_status` 时，已通过和待核对的题都返回（列表里靠标记区分）。
- `GET /api/questions/review/count`：返回待核对的题数，给首页和导航上的数字用。
- `POST /api/questions/{id}/review`，内容 `{"action": "approve"}` 或 `{"action": "reject"}`。
  - 通过：题目必须有主考点，否则返回 422 并提示先选考点。状态改为已通过，记下处理时间。
  - 移除：软删除，状态记为 `rejected`，记下处理时间。
  - 只对待核对的题有效，其他状态返回 409。
- "改后通过"由页面分两步完成：先用现有的 `PUT /api/questions/{id}` 保存修改，再调通过。`PUT` 这次要接受两个新字段：`wrong_answer`、`question_no`。这次不支持把一道题挪到另一份卷子下。**【Claude 定】**

### 6.5 卷子接口

- `GET /api/papers`：分页列表，可按学科、类型筛选。每条带题目数和待核对数，用一条聚合 SQL 算出，不逐条查。
- `GET /api/papers/{id}`：一条记录的详情和它下面的题目。
- `POST /api/papers`：页面上手工新增（比如只记一个考试分数）。`source` 记为 `manual`。
- `PUT /api/papers/{id}`：改名称、类型、日期、年级学期、分数、备注。校验规则和 6.2 的卷子部分相同。学科不能改（考点是按学科分的）。改年级或学期时，这份卷子下的题目在同一个事务里跟着改，因为统计是按题目上的年级学期筛选的。`source` 为 `history` 的记录只能改名称和备注。**【Claude 定】**
- `DELETE /api/papers/{id}`：软删除。下面有题目时，必须带参数明确表示"连同题目一起删"，否则返回 409。`source` 为 `history` 的记录不允许删除。

## 7. 录入规范和小工具

### 7.1 放在哪里

问题：用户是在主目录 `D:\code\easyfix` 里打开 Claude 或 Codex 录题的，而那个目录停在很早的版本、不能动。把规范写进仓库的 `AGENTS.md`、`CLAUDE.md`，在那个目录里开的对话读不到。

做法：**【Claude 定，需要用户点头，因为要往仓库之外的用户目录里放文件】**

- 规范和小工具放在仓库的 `tools/easyfix-intake/` 目录下，随代码一起管理版本：
  - `SKILL.md`：录入规范。写成 Claude 和 Codex 都认的"技能"格式。
  - `easyfix_intake.py`：录入小工具。只用 Python 自带的库，不依赖仓库里的其他代码。
  - `install.py`：安装脚本。
- 安装脚本把这个目录复制到 `~/.claude/skills/easyfix-intake/`（Claude 读这里）和 `~/.agents/skills/easyfix-intake/`（Codex 等其他工具共用的技能目录）。这两处是用户级的技能目录，在任何文件夹里开对话都会读到，不受主目录版本的影响。原先写的是 `~/.codex/skills/`，写计划时查到 Codex 实际读的是 `~/.agents/skills/`，已改正。
- 接口地址和访问口令放在用户目录下的 `~/.easyfix/intake.json`，不进仓库，不写进任何文档和对话。
- 仓库的 `AGENTS.md` 和 `CLAUDE.md` 各加一小节，说明录题只能用这个技能，并把 `AGENTS.md` 里"使用结构化参数写库"那句旧说法改掉。`CLAUDE.md` 整体还是旧版本地系统的说明，这次只加这一节，不重写。
- 规范更新后要重新运行安装脚本。忘了也不要紧：小工具带着版本号，和服务端不一致时提交会被拒绝并提示更新。

实施时要实测：在主目录里新开一个 Claude 对话和一个 Codex 对话，各贴一张照片说"录入错题"，确认它们用上了这个技能。如果 Codex 不自动读取用户级技能目录，退一步在 `~/.codex/AGENTS.md`（目前是空文件）里加一段指向它的说明。

录入规范不是写完就算数。它按"先看助手在没有规范时怎么做错，再写规范，再用同样的卷子验证"的办法来写：用 2–3 份真实卷子的照片做场景，对照人工核对过的标准答案，检查有没有把做对的题录进来、页码对不对、拿不准的有没有标出来、有没有绕过小工具。照片只留在本机被忽略的目录里，不进仓库。

### 7.2 小工具的命令

| 命令 | 作用 |
| --- | --- |
| `guide --subject 数学 [--grade 6 --semester 1]` | 取录入资料，输出 JSON |
| `upload 照片1 照片2 ...` | 按顺序上传照片，输出存储路径 |
| `check 文件.json` | 试提交，只检查不写入，列出每道题的问题 |
| `submit 文件.json` | 正式提交。内部先自动试提交一遍，通过后才写入 |

小工具不负责识别，只负责和接口打交道。它自己不重复实现校验规则，以接口返回的结果为准。

### 7.3 录入规范的内容（`SKILL.md`）

写给 Claude 和 Codex 看的工作步骤和规则：

1. **只走小工具。** 不直接写数据库，不临时写导入脚本，不调用旧的批量接口。
2. **先取资料。** 运行 `guide` 拿到考点清单和错因清单。学科从卷面内容判断；年级学期用户没说时用应用默认值。
3. **只录错题；先验算，再认符号。** 每道题自己做一遍。不同老师的批改符号含义不一样（真实卷子里见到：数学老师的长斜线表示对，英语老师划在选项上的斜线表示错），所以要用验算结果去确认这位老师的符号是什么意思，不能只凭符号的形状。**【Claude 定，来自真实卷子】**
   - 符号表示错，验算也是错：录入。
   - 符号表示对，验算也是对：不录。
   - 符号和验算对不上：录入并标待核对（`wrong_unclear`），说明里写清哪里对不上。
   - 老师没有批改，验算发现写错了：录入并标待核对（`wrong_unclear`），说明里写"老师没有批改这一题"。**【用户定】**
   - 老师没有批改，验算是对的：不录。
4. **每道题写清楚：** 在第几张照片、题号、题干、正确答案、解析、孩子写的答案、判错依据、错因、考点。
5. **不猜。** 照片缺字或被裁切时不补全；看不清孩子写了什么时 `wrong_answer` 留空；用户没说年级学期、卷面也看不出时用默认值，不自己推断。不因为题型复杂就把错因标成"计算"。
6. **考点只从清单里选。** 选一个主考点，可以再选关联考点。清单里找不到合适的，不硬套，把这题标为待核对，原因 `kp_unsure`。
7. **拿不准就标待核对，并写明原因：** 不确定是否做错（`wrong_unclear`）、照片模糊或题干拿不准（`text_unclear`）、考点拿不准（`kp_unsure`）、其他（`other`）。在 `review_note` 里用一句话说清楚疑问在哪。
8. **数学公式** 沿用现有规范：行内 `\(...\)`，独立公式 `\[...\]`，次方带花括号，分数用 `\frac{a}{b}`。
9. **提交前问用户一句。** 如果用户没有说明这是哪份东西，问："这是哪份作业或卷子？如果是考试，多少分？可以回'跳过'。"只问这一次。用户跳过就不填名称、类型和分数，由系统给默认值。
10. **照片。** 用对话里附件的本机文件路径上传。已核对过：贴进 Claude 桌面版和 Codex 的图片都会在本机临时目录里留一份文件，对话里带着路径。但这份文件可能是压缩过的（见过 140KB 左右的），清晰度够不够用要实测。拿不到文件路径时告诉用户，由用户决定是给出照片所在位置还是不带照片录入。
11. **提交后向用户汇报：** 录了几道、几道直接入库、几道待核对及各自原因、待核对页面的地址。
12. **系统里没有的学科不录。** `guide` 返回的学科列表里没有的学科（比如语文），不录，并告诉用户这份没有录和原因。**【Claude 定】**

不做每次录题前的手工备份。写入走接口后有事务保护，数据库本身保留 30 天的时间点恢复。**【Claude 定】**

## 9. 统计口径

规则：**凡是"数题目""算比例""挑题目"的地方，只看未删除且已通过的题。**

做法：把这个条件写成一处共用的 SQL 片段，下面这些地方都引用它，不各写各的。

需要加上条件的地方：

- `knowledge_stats.py`：`module_stats`（考点统计的核心，分析页和报告都用它）。
- `analytics.py`：`grouped`、`primary_module_counts`、`summary`（首页）、`date_stats`、`full`。
- `reports.py`：`generate`。
- `practices.py`：`generate_questions`（自动选题）、`create_set`（手工建卷时拒绝待核对的题）。
- `similar.py`：`generate`（待核对的题不能生成相似题，返回 409）。

不加条件的地方：

- 错题列表和详情：待核对的题要能看到。
- 考点目录的"被多少题使用"和删除保护、学科的删除保护：待核对的题也占着关联，仍然计入。

## 16. 实施中的调整（2026-11-11）

下面是实施过程中对前文的补充和修改。有冲突时以本节为准。每条标了来源。

### 16.1 录入接口多了三类检查和一个必填项

来由：录入规范的实测里，下面几类问题靠文字提醒挡不住，改成由接口来挡。**【Claude 定】**

- **必填的 `parent_reply`**（请求顶层，1–200 个字符）：家长关于"这是哪份卷子"说了什么，可以是家长的原话、`跳过` 或 `家长说不用问`。不写就不能试提交和正式提交。它不入库。来由：第一轮 11 次里有 4 次没问那一句就提交了；加了之后两轮都是 0 次。
- **被写坏的公式和文字整份退回**。文字里出现换行以外的控制字符；公式里出现换行；矩阵、方程组这类多行公式里换行丢失（反斜杠只剩一个）；公式外面出现反斜杠。每种都有固定的中文提示，告诉助手怎么改。来由：三轮实测里每轮都有助手把公式的反斜杠写坏，形式各不相同。
- **年级学期没给时由接口补上应用默认值**。来由：第一轮有 5 次没填，题目入库后按年级筛选的统计看不到它们。

`SPEC_VERSION` 仍为 1，因为接口还没有发布过。6.2 节的请求示例要加上 `"parent_reply": "跳过"`。

### 16.2 考点目录追加了四个考点

**【用户定：同意追加】** 2026-11-11 已写入正式库并回读核对，记录见 `docs/cloudflare-migration-status.md`：

- 简单的代数式：用字母表示数与列代数式、代数式的书写规范、代数式的意义
- 规律探索与综合应用：图形与数字排列规律

来由：目录是按已有错题整理的，第二章只有两个考点。实测里第二章的一页作业 11 条全部因"目录里找不到考点"进了待核对；补上后同一页三次实测都是 8 条里 7 条直接入库。

**尚未决定的问题**：以后再遇到目录里确实没有合适考点的题，是直接入库记为未分类，还是像现在这样放进待核对。现在的行为是后者。用户选择先补目录，这个问题留待以后定。

### 16.3 录入规范（7.3 节）的补充

以下都已写进 `tools/easyfix-intake/SKILL.md` 和 `payload-format.md`，并经过三轮实测。**【除注明外均为 Claude 定】**

- 每页先把每道题自己做一遍并列出清单（做对了 / 做错了 / 老师没批改且我判断错 / 无法判断），再看老师的符号；给家长的汇报里写明每页有几道题、录了几道。
- 老师明确判错的题一律录入。孩子的答案有涂改时，看到的可能是订正后的字，不能当成孩子的答案，也不能据此认为做对了；答案留空，直接入库，不标待核对。
- 老师的符号看不懂、自己也做不出：录入并标待核对。老师符号清楚、自己做不出：以老师的批改为准。老师没批改、又无法判断孩子做错没有：不录。
- 红笔只是划过或挨着某道题、不是明确针对它的符号，按"老师没有批改"处理。
- 数值对但写法被老师判错（比如字母写在数字前面）：这是书写规范的真错误，正常录入，不算"符号和验算对不上"。
- 孩子的答案一字不差照抄；有一个字符拿不准就整项留空。
- 带小问的大题：小问各算各的，做错的各记一条，题号写成"4(3)"；小问共用同一段题干、图、表、定义或已知条件的，整道大题记一条。
- 题号按卷面印的写法。日期只有在年月日都明确时才填。
- 考点先在整个目录里找最贴近的，包括别的模块；确实没有才留空，并在汇报里告诉家长缺的是哪类考点。
- 老师没有批改、但验算发现写错的题：录入并标待核对，说明以"老师没有批改这一题"开头。**【用户定】**
- 系统里没有的学科（比如语文）不录，不问要不要新建学科。
- 提交文件用脚本生成，不手写反斜杠。提交后才发现有内容存坏了，不重复提交，告诉家长哪道题要在页面上改。

### 16.6 实测之后仍然会偶尔出现的情况

第三轮 6 次运行里各出现一到两次：漏掉一道真的做错的题；孩子的答案看不清时猜了一个字；多标了一个待核对；"老师没有批改"的说明没按规定开头。三轮 26 次提交里没有出现过把做对的题录进来，也没有出现过绕开小工具。

最后一次对录入规范的修订只做了静态审阅，没有再跑场景。这些偶发情况靠待核对页和卷子页兜底：漏了可以手工补，多了可以移除。

### 16.7 整体审阅之后的调整（2026-11-11）

整个分支做完后做了一次整体审阅，没有发现会损坏或隐藏旧数据的问题。下面几处按审阅意见做了修改。**【均为 Claude 定】**

- **卷子详情分批显示题目**（改 6.5 节）：`GET /api/papers/{id}` 增加 `skip`、`limit`（默认 50，最多 100），页面先显示 50 道，点"加载更多"再取 50 道；题数和待核对数仍是整份卷子的总数。来由：旧题回填出的历史记录下面有几百道题。
- **重复提交不再悄悄"成功"**（改 6.2 节的防重复）：同一个 `request_id` 原样再交，仍返回第一次的结果，小工具会多说一句"之前已经提交成功过，这次没有再写入"；内容和第一次不一样，或者那份记录已经被删除，接口返回 409 并说明要重新生成提交文件，小工具退出码为 2。来由：家长删掉一份录坏的记录后让助手重录，助手沿用旧文件会得到"成功"但什么都没存进去。
- **旧题回填**（改 5.5 节）：一组旧题全部是已删除的，为它建的历史记录也标为已删除，不显示在卷子页；年级为空的组，名称里带上学期；回填语句可以重复执行，不会建出重复的历史记录。
- **公式里的换行有单独的提示**；Windows 换行（回车加换行）不再被当成写坏的反斜杠。
- 安装脚本的 `--codex-pointer` 开关接上了；配置文件带 BOM（记事本、PowerShell 存出来的）也能读；小工具的 `--help` 会列出退出码。
- 照片路径和日期的格式检查收紧（不接受末尾换行、控制字符、全角数字）；两处格式不对的请求原来会报服务器内部错误，现在返回明确的提示。

**已知但没有在发布前处理的事**（都不影响旧数据，可以之后再做）：

- 待核对的题要有主考点才能"通过"。如果某个年级没有考点目录，因为别的原因待核对的题只能先借用别的年级的考点，或者移除。这和 16.2 里"目录里没有合适考点怎么办"是同一个待定问题。
- 待核对超过 100 道时，页面只显示前 100 道，没有提示。
- 历史记录的年级或学期如果不在正常范围内，改名会被拒绝。正式库里旧题的年级只有五年级、六年级和未填，发布演练时会再确认一次。
- 文字字段没有长度上限；在错题页修改一道题的年级学期后，它会和所属卷子不一致；上传的照片保留原文件名，文件名里有 `#`、`?`、`%` 时图片地址会坏。

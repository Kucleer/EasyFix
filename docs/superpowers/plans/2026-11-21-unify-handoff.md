## 6. 这台机器上的实际情况

这些是前几次发布踩出来的，文档里的命令有些在本机不能直接用。

- **Wrangler**：`cloudflare/tools/cli.cjs` 包装器需要 `tmp/cloudflare-config`，本机没有。实际用的是 `D:/code/easyfix-cloudflare-inspect/cloudflare/node_modules/.bin/wrangler`（4.158.0，已登录）。
- **代理**：本机设置了 `HTTP_PROXY` / `HTTPS_PROXY`。运行 Wrangler 的普通命令（部署、D1、R2）前要先 `unset HTTP_PROXY HTTPS_PROXY http_proxy https_proxy`，否则超时；只有 `wrangler tail` 相反，必须保留代理。
- **Python 后端依赖**：新工作树里没有 `cloudflare/python_modules`，部署前要从 `pylock.toml` 相同的检出里复制过来。2026-11-20 那次发布发现主检出里的这个目录不完整，已按 `pylock.toml` 重建过；部署前确认里面有 `fastapi`。
- **前端依赖**：`frontend/node_modules` 有一部分被 git 跟踪，直接 `npm run build` 会弄脏它和 `frontend/dist`。在工作树里先 `npm install --legacy-peer-deps`（缺 `d3-force`、`katex` 时），构建只用 `python backend/scripts/prepare_cloudflare_frontend.py`。
- **Pages 发布是整站替换**：必须从包含线上全部前端功能的代码构建，发布命令在 `cloudflare/pages` 目录下执行。
- **Worker 部署错误 10021**（"binding DB of type d1 failed to generate"）是临时的，隔几分钟重试即可。但如果报的是 `No module named 'fastapi'`，那是依赖目录不完整，不是临时错误。
- **后端每个请求都超过免费计划 10 毫秒的 CPU 限额**，偶尔会返回 502"云端请求失败"，隔几秒重试即可。
- **本地开发服务器** `cloudflare/scripts/local_dev_server.py` 自己搭应用，不加载 `main.py`，只登记了一部分路由模块（见它的 `ROUTER_MODULES`）；`auth`、`motivation`、`media`、`words`、`readings` 等模块本机导不进来。所以计划里的清单测试是读源码文本来判断的。
- **换行**：仓库开了 autocrlf，工作区文件是 CRLF。改已有文件时保持原来的换行，不要整文件改成 LF。
- **本机没有访问密码**：需要登录才能看的东西验证不了，要交给用户核对（计划任务 6 里有一份 6 条的清单）。
- 录入小工具的接口地址和口令在 `~/.easyfix/intake.json`，**任何时候都不要把口令打印出来或写进文件**。

## 7. 实施时容易踩的地方

- **同名不同物**：`questionApi.createBatch`（要删）和 `wordApi.createBatch`（在用，不能删）；`statsApi.getKnowledgePoints`（要删）和 `learningAnalysisApi.getKnowledgeStats`（在用）。
- **`catalog.py` 是一个循环统一注册路由的**：`get_item` 函数被保存和删除在内部调用，只去掉它的路由，函数留着。
- **`media.py` 里要删的和要留的挨在一起**：读音播放和打印单词必须留。
- **`reports.py` 只删"生成"**：列表、详情、删除要留，旧报告页还在用。
- **两个测试用例是整个删掉的**（测的就是要删的功能）；**`worker.test.mjs` 里测转发的那个用例是换例子，不是删**。计划里写明了各是哪个。
- **设计第 10 节列了更多要删的东西**（旧首页统计、旧学情统计、批量生成相似题等），那些现在还有页面在用，属于第 3 步，计划的 Global Constraints 里列了不动的清单。
- 未登录请求会被统一拦成 401，所以发布后没法用"返回 404"来证明某个接口已经删掉，只能靠清单测试和用户登录后的核对。

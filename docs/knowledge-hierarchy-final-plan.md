# EasyFix 两级知识点全局改造方案

日期：2026-11-10（北京时间）  
状态：已核对并整合 Claude Review，完成二次修订（2026-11-10）；本文件是实施规格，不代表功能已实现或数据已迁移。Review 意见及二次修订见第 13、14 节。
适用环境：Cloudflare Pages + Python Worker + D1 / R2 正式架构。

## 1. 目标与范围

用户要求：知识点采用两级结构；统计与分析默认展示一级；错题展示具体二级。

最终决策：

1. 一级为学科知识模块，二级为可用于归类、复习的具体考点。只允许两级。
2. 每个二级只属于一个同学科一级；一道题可关联多个二级，并有且仅有一个主考点（未分类题除外）。
3. 统计默认按一级聚合，支持点击下钻二级；题目展示二级，提供一级上下文。
4. 结构化 ID 关联是唯一业务事实来源，名称不再承担身份识别。
5. 教材章节不是知识点的父级；不同版次章节与知识点可以多对多关联。本期不建设完整教材管理系统。
6. 不改写题干、答案、解析、公式、图片、原年级学期及既有作答记录，不自动推断学生错误类型。
7. 覆盖所有正式读写入口和衍生输出，不允许页面改为二级后，批改或 Agent 继续产生自由文本标签。

本次文档交付不执行数据库变更、应用发布或模型调用。正式实施按本文件第 12 节执行完整分支、验证、合并、推送和部署流程。

## 2. 已核实的现状与风险

基于本仓库源代码盘点：

- `question.knowledge_point` 是单个文本字段；`knowledge_point` 是平铺目录，尚无父子结构。
- `cloudflare/src/main.py` 的错题查询使用文本子串过滤；列表与详情有独立的数据装配路径。
- `cloudflare/src/questions.py` 的单题保存和批量入库为不同流程，必须同时适配。**单题保存当前不是原子的**：先单独执行 `UPDATE/INSERT … RETURNING *`，再另起 batch 写标签；批量入库则已用“预分配 ID + write_guard”在一个 batch 内完成。
- `analytics.py`、`reports.py` 直接按名称分组；图谱按名称关联题目，目前返回空边列表。
- 现有知识点正确率、报告 `overall_accuracy`、错题列表 `accuracy_range` 筛选、自动组卷优先级均使用 `question.review_count/correct_count/error_count` 累计计数器；`mark-reviewed` 每次批改都累加（重复批改同一练习也累加），而 `practice_set_question.is_correct` 是覆盖写。
- 学习报告的 `question_analysis.top_error_knowledge_points`（含 count）由模型按提示词输出，`reports.py` 只用服务端数值覆盖 `overview`；`LearningReports.vue` 把该 count 标为“错误次数”。
- 上传和错题编辑使用名称选择；练习批改弹窗仍可直接输入知识点文本，且保存时总会携带 `knowledge_point` 字段。
- `kp_error_type` 保存知识点与错误类型关系，上传和编辑按所选知识点过滤错误类型。
- 相似题提示词、练习详情、PDF 渲染及 PDF 内容指纹均消费旧文本。
- `cloudflare/src/prompts.py` 是生成文件：`backend/scripts/prepare_cloudflare_prompts.py` 会从 `backend/app/services/llm.py` 重新生成它；`backend/scripts/refine_cloudflare_queries.py` 会对 `cloudflare/src` 做字符串替换。重跑这两个脚本会覆盖本次改造。
- 前端知识点颜色另有模块级内存缓存（`loading` 永不重置），不等同于 HTTP 缓存；`http.js` 的 5 分钟目录缓存正则只匹配以 `/knowledge-points` 结尾的 URL。
- 阅读练习临时拼接 `阅读理解-主题` 作为知识点，不能直接当正式目录身份。
- `catalog.py` 以通用 `register()` 循环注册 `knowledge-points`，`/{item_id}` 无 int 转换器，新增 `/tree` 若注册在后会被 `get_item` 匹配并返回 422。
- 维护开关现状：`MIGRATION_READY` 是 Worker 环境变量，修改需重新部署；`auth.py` 对 `Bearer ACCESS_TOKEN` 请求（Agent）直接放行写入，因此关闭它**拦不住 Agent**；拦截文案仍为“请暂时继续使用原入口”。
- Agent 批量入库的调用方不在本仓库内，其提示词/技能文档需单独更新。
- 正式数据源是云端 D1；旧 `backend/app/` 及部分旧脚本仍有旧结构，禁止用其写生产。

2026-11-09 的只读快照曾包含 557 道有效错题（数学 319、英语 238）。这是历史盘点值，实施时必须重新查询，不能用此数作为固定验收基线。此前 489 道关键词候选未人工确认，不能直接当迁移映射。

## 3. 分类设计

### 3.1 一级目录建议

数学六上：有理数、简单的代数式、一元一次方程、线段与角。历史题还需覆盖小数、整除、分数、比与百分数、平面图形、立体图形等模块；不能仅创建当前六上四章而丢弃五年级知识。

英语：名词与数量表达、代词、动词与时态、形容词与副词、冠词与介词、句法、交际表达、词汇与搭配、语音、阅读理解、书面表达。二级边界按实际题目审定，例如“物主代词”只归“代词”，不得同时在“词汇与搭配”建立同义副本。

上述是目录设计建议，不宣称所有条目均为教材原文。正式种子清单必须单独审阅，包含稳定编码、学科、一级、二级、定义及典型边界；不要把教材主题、题型、错误类型混成同一分类维度。

## 4. 数据结构与不变量

以下为逻辑规格；实施时先核对 D1 当前 schema，再编写追加迁移，不修改或重放旧快照。

### 4.1 扩展 `knowledge_point`

| 字段 | 约束与用途 |
| --- | --- |
| id | 保留既有主键；新节点使用新 ID |
| code | 稳定唯一编码；旧数据过渡期可空，迁移完成后所有有效节点必须有值 |
| name | 展示名；trim 后非空 |
| name_key | 规范化比较键（trim、全半角统一、英文小写），由应用层写入并受唯一索引约束 |
| subject_id | 有效学科，禁止跨学科父子关系 |
| level | 正式目录为 1 或 2；待处理历史行可为 NULL，只读保留，不属于有效两级目录 |
| parent_id | 一级为空；二级必须指向有效一级 |
| sort_order | 同级排序，默认 0，再按 ID 排序 |
| grade / semester | 保留旧字段，仅作推荐筛选；不作为知识点身份，不限制历史题挂接 |
| deleted | 继续软删除 |
| created_at / updated_at | 保留创建时间，新增更新时间 |

唯一性：有效一级在同学科内 `name_key` 唯一；有效二级在同一父级内 `name_key` 唯一。使用分别适用于一级、二级的部分唯一索引（`WHERE level=1 AND deleted=0` / `WHERE level=2 AND deleted=0`），避免 NULL 父级导致唯一约束失效。SQLite 唯一索引默认区分大小写，因此规范化规则必须落在 `name_key` 上，不能只写在种子清单或前端。

数据库保护分两层，避免触发器过重：

- **触发器（必须）**：
  - `question_knowledge_point` INSERT/UPDATE：目标必须是 `level=2`、未删除、与题目同学科的节点；
  - `knowledge_point` INSERT/UPDATE：`level=2` 时父级必须是同学科、未删除的 `level=1`；`level=1` 时 `parent_id` 必须为空；拒绝第三级；允许 `level IS NULL` 的旧行存在，但它们不能被新关联引用；
  - `question` `UPDATE OF subject_id`：存在有效关联且关联目标不属于新学科时拒绝；
  - `kp_error_type` INSERT/UPDATE（`deleted=0`）：只能挂在 `level=2` 节点。
- **应用层 + 一致性校验脚本**：一级有有效子级时禁止软删除；二级有有效题目关联时禁止软删除；有子级或引用的节点禁止改学科、改层级；学科下有有效知识点或题目时禁止软删除。部署后及每次迁移批次后运行只读一致性校验脚本，发现违规即停止。

“有效题目关联”指 `question_knowledge_point.deleted=0` 且 `question.deleted=0`；已删除题目的旧关联不阻止删除二级。

应用层检查必须落实为同一个 D1 batch 中的条件断言与写入，或等效触发器，不能采用“先 SELECT、再无条件 UPDATE”：否则检查后仍可并发新增引用。一级/二级删除、改学科/层级、二级移动和学科删除均需要数据库内原子保护。恢复软删除题目或关联时重新验证全部目标有效性，不得恢复出悬空分类。

触发器的 `RAISE(ABORT, '<稳定错误码>')` 消息需使用固定前缀（如 `KP_LEVEL`、`KP_SUBJECT`），应用层按前缀映射为 409/422 并返回中文说明，不得落入全局中间件的通用 500。

### 4.2 新增 `question_knowledge_point`

| 字段 | 约束与用途 |
| --- | --- |
| id | 主键 |
| question_id | 原错题 ID |
| knowledge_point_id | 只能关联有效同学科二级 |
| is_primary | 0/1；有分类的有效题目必须恰好一个主考点 |
| source | manual / migration / agent |
| deleted | 软删除；取消关联不硬删 |
| created_at / updated_at | 关联时间 |

建立 `(question_id, knowledge_point_id)` 唯一约束，重复添加恢复原关联；建立有效主考点的部分唯一索引（`ON (question_id) WHERE is_primary=1 AND deleted=0`），保证每题至多一个主考点。建立按知识点反查题目的索引，避免逐条查询。

`question` 新增 `knowledge_revision INTEGER NOT NULL DEFAULT 0`。

**原子写入的 D1 实现方式（必须遵守）**：D1 batch 是事务，但条件 UPDATE 匹配 0 行不会报错，后续语句会照常执行。因此沿用项目已有的 `write_guard` 模式（见 `questions.py` 批量入库、`practices.py` 删除）：

1. 批次第一条：`UPDATE write_guard SET revision=CASE WHEN (SELECT knowledge_revision FROM question WHERE id=? AND deleted=0)=? THEN revision+1 ELSE NULL END WHERE id=1`；版本不符时 NOT NULL 失败，整批回滚，返回 409。
2. 题目内容 UPDATE、旧关联软删除、新关联 upsert、主考点设置。分类或学科实际变化时 `knowledge_revision=knowledge_revision+1`；先清理旧主考点再设置新主考点，避免部分唯一索引冲突。
3. 批次最后一条：使用事务内断言校验“有有效关联的题目恰好一个有效主考点、无关联的题目没有主考点”，不满足则整批回滚。可使用专用 CHECK 断言或 write_guard；不是事务外读回后补救。

应用层捕获 batch 异常后，区分版本冲突（409）、分类校验失败（422）、引用约束（409）、维护停写（503）与未知故障（500）。版本守卫和末尾结构断言不能共用无法辨认的 NOT NULL 错误后全部归为版本冲突：采用可区分的 CHECK/触发器错误码，并在隔离 D1 验证实际异常格式。

`write_guard` 单例必须存在、未删除，迁移预检及事务断言检查此条件；守卫行缺失不能因 UPDATE 0 行而继续后续写入。

新建题目在同一 batch 内无法从 Python 拿到新 ID，因此单题新建与批量入库统一采用“`MAX(id)+n` 预分配 ID + `write_guard` 校验 MAX(id) 未变化”的现有模式。单题和批量路径共用同一套校验与写入语句构造逻辑，`save()` 需按此重写，读回放在 batch 之后。

集合校验（知识点是否存在、是否同学科二级、错误类型是否属于学科）一律用 `json_each(?)` 一次查询完成，不得照搬现有“每个 ID 一次 SELECT”的写法；单条 SQL 绑定参数不超过 100 个。

只修改题目内容、不传知识点字段时不要求 `knowledge_revision`，内容仍为后写覆盖（与现状一致）。

`knowledge_revision` 仅在分类、主考点或学科发生实际变化时递增；普通内容修改和旧投影无变化回传不递增。题目改学科需在事务中先软删除旧关联，再更新学科，再写入新关联，最后验证唯一主考点，以符合即时触发器约束。兼容旧文本发生分类变化时必须带版本；没有版本返回 409 并提示刷新，不能读最新版本替调用方绕过并发保护。

### 4.3 旧字段与兼容

- `question.knowledge_point` 保留为旧客户端兼容投影；历史原值在备份及私有迁移清单中保存。
- 新业务查询、统计、生成均不能依赖该文本字段。兼容投影只输出主考点二级名，不用分隔字符串编码多选。
- 无关联时返回 null；原未解决文本作为明确命名的只读 `legacy_knowledge_point` 返回，不伪装成新分类。
- 为使原标签能经业务 API 回查，`question` 新增只读 `legacy_knowledge_point` 列，回填时保存切换前原文本；不随新分类编辑或兼容投影更新而覆盖。私有迁移清单和备份是额外证据，不能作为日常 API 的唯一数据来源。
- 未传知识点字段表示保留原关联；`knowledge_point_ids` 传空数组表示明确清空；清空后无主考点。新旧字段同传且矛盾则 422。
- 旧文本字段 `knowledge_point` 的处理顺序：
  1. 值等于该题当前兼容投影（主考点名），或均为空/null：视为“未修改”，**保留全部现有关联**（防止旧页面回传主考点名时把次要考点清掉）；
  2. 空字符串且当前有关联：视为“未修改”，不清空；旧客户端无法表达清空，清空只能通过新字段；
  3. 其他值：仅当在同学科内唯一、明确匹配一个有效二级时，转换为“以该二级为主考点”，**保留原有其他关联**作为次要考点；同名多候选或未知标签返回 422，不自动创建目录。

### 4.4 分类管理规则

- 改名保持 ID，统计随新名显示；历史报告保留生成时名称快照。
- 一级有有效子级、二级有有效题目关联（定义见 4.1）时禁止直接删除，返回 409 和引用数量。
- 移动有题目关联的二级会重分配全部历史统计：本期禁止；需要另走显式数据迁移并展示受影响数量。
- 有子级或引用的节点禁止改学科、改层级；不要级联静默删除。
- 学科下仍有有效知识点或题目时禁止软删除学科（现有通用 catalog 删除不检查引用，本期补上）。
- 题目修改学科时，必须在同一请求中提交新学科下的 `knowledge_point_ids`（可为空数组）；否则返回 422，由触发器兜底。
- `kp_error_type` 的有效配置只落在二级。迁移先合并去重旧映射，保留同学科或通用错误类型；多个二级的候选错误类型取并集。已有错误类型不因分类变化被自动清空或判定错误。

## 5. 统一统计口径

所有统计先构造筛选后的有效题目集合，再关联有效二级和父级；必须过滤题目、关联、二级、一级、学科的软删除状态。

| 指标 | 固定口径 |
| --- | --- |
| 一级错题数 | `DISTINCT (question_id, parent_id)` 后按一级计数 |
| 二级错题数 | 每个二级内按 question_id 去重 |
| 一级占比（加总 100%） | 仅按主考点所属一级归属；无分类计“未分类” |
| 复习覆盖 | 所属模块中有有效已批改错题练习记录的去重题数 / 模块去重题数 |
| 模块练习正确率 | 有效已批改作答中正确次数 / 作答总次数；同一次作答在同一级只计算一次 |
| 零作答模块 | accuracy 为 null，显示“暂无练习记录”，不得显示 0% 或自动判为薄弱 |
| 未分类 | 没有有效二级关联的题目，单独计数；不创建虚假的“其他”节点兜底 |

正确率使用 `practice_set_question` 与 `practice_set` 的有效、来源为 question、已批改记录，按练习条目身份（`practice_set_question.id`）去重；原题和相似题均纳入，明确是“练习作答正确率”，不宣称细考点诊断准确率。一级/二级只通过该条目关联的原题获取分类，不混入单词和阅读练习。不把复习计数直接乘上多标签 JOIN 后求和。

**两套正确率的边界**：本期不改动 `question.review_count/correct_count/error_count` 累计计数器及其现有消费者（错题列表 `accuracy_range` 筛选、自动组卷优先级、题目级复习次数）。界面命名区分：

- “模块练习正确率”：本节口径，来自 `practice_set_question` 最终批改状态，用于一级/二级统计和报告模块指标；
- “累计批改正确率”：来自题目计数器，重复批改同一练习会累加，仅用于题目级展示和现有筛选。

同一页面同时出现两者时必须使用上述名称，并在帮助说明中解释差异；`/api/stats/knowledge-points` 和报告模块部分不得再用计数器计算知识点正确率。

**时间窗口**：带时间范围的统计（如报告 `time_range_days`）中，题数类指标按题目收录时间 `question.created_at` 筛选（与现状一致）；模块练习正确率按练习批改时间 `practice_set.last_reviewed_at` 筛选。两者共享学科、题目年级等适用筛选，但正确率不叠加题目收录时间筛选，允许旧题在本期的练习进入指标。两者口径在报告快照中记录；无效/缺失批改时间不猜测补齐，列出排除数量。

本期没有逐次批改事件表，统计反映当前保留的有效练习条目及最终批改状态，不宣称覆盖所有历史重复批改。模块归属采用题目当前分类；分类调整后历史练习会按新分类重算，界面帮助说明这一点。历史学习报告仍保留当时快照。

示例：Q1 同时关联“有理数/乘方”“有理数/混合运算”，Q2 关联“线段与角/角的和差”和“一元一次方程/解方程”。Q1 在有理数计 1；Q2 在两个模块各计 1。模块覆盖数之和可大于总题数，界面需提示；占比图按主考点才可相加。禁止对子考点正确率做简单平均，必须汇总去重后的分子分母。

报告标题统一“高频收录错题模块”，计数单位为“题数”；真正的练习错误次数另列，修正当前报告中以“错误次数”展示收录题数的歧义。

## 6. API 合约

不新增另一套平行业务 API；扩展现有路径，新增字段，并在消费者全部升级后停止旧字段依赖。

### 6.1 目录

- `knowledge-points` 从 `catalog.py` 的通用 `CATALOG` 注册中移出，由新的 `cloudflare/src/knowledge.py` 单独注册路由并集中实现父子校验、引用计数、409、错误类型只挂二级等规则；其余实体仍走通用注册。
- `GET /api/knowledge-points` 保留平铺响应，增加 level、parent_id、code、sort_order；支持 level、parent_id 与已有筛选。
- 增加 `GET /api/knowledge-points/tree` 返回两级树，并附带当前 `taxonomy_version`。`/tree` 必须注册在 `/{item_id}` 之前。
- 树筛选按子级匹配，再补齐父级；不能因一级 grade/semester 为空而隐藏有效二级。
- CRUD 校验遵循第 4 节；错误类型配置只允许二级。目录写入与 `taxonomy_version` 递增在同一 batch 内完成。

### 6.2 题目

创建、修改、批量入库统一增加：

```json
{
  "knowledge_point_ids": [101, 102],
  "primary_knowledge_point_id": 101,
  "knowledge_revision": 3
}
```

以上 ID 仅为合约示例。新建可省版本；修改分类必须传读取时的版本。非空列表必须显式提供其中一个主考点；空数组要求主考点为空。允许未分类题目，不强制用户猜测。

批量入库（Agent）：每题可各自提供 `knowledge_point_ids` / `primary_knowledge_point_id`，`source` 记为 `agent`。知识点校验失败按现有语义计入该题的 `errors` 并跳过该题，不影响同批其他题目；整批只在学科、错题本、年级学期等批次级参数无效时拒绝。旧文本 `knowledge_point` 按 4.3 规则转换，无法唯一匹配时该题进入 `errors`，不入库为无结构文本。

列表、单题详情、保存响应、批量入库响应、练习题详情统一返回：

```json
{
  "knowledge_revision": 4,
  "knowledge_points": [
    {"id": 101, "name": "乘方", "parent_id": 10,
     "parent_name": "有理数", "subject_id": 1, "is_primary": true}
  ],
  "knowledge_point": "乘方",
  "legacy_knowledge_point": null
}
```

练习详情中条目的 `id` 是 `practice_set_question.id`，知识点必须按条目的 `question_id` 批量装配。

筛选参数新增 `knowledge_parent_id` 和 `knowledge_point_id`；二者同传必须属于同一路径，否则 422。选择一级查询其全部有效二级；用 EXISTS 避免列表重复和分页总数膨胀，一级的子级集合用子查询而非绑定参数展开。旧名称筛选可保留明确的兼容转换，不再用子串匹配承担精准知识点筛选。关键词搜索覆盖两级名称，但独立于精准筛选。

`filter-options` 保留旧字段供过渡，新增 ID/父子结构数据（来自目录而非题目文本 DISTINCT）。正式前端只消费新字段。

### 6.3 统计与报告

- `/api/stats/summary`、`/api/stats/knowledge-points`、`/api/stats/analysis/full` 的知识点部分统一使用一级，返回模块 ID、学科身份和指标分子分母。
- `/api/stats/knowledge-points` 增加 `level=1|2`，默认 1；二级查询必须指定 parent_id。
- 聚合结果返回 `taxonomy_version`、`counting_mode`、`unclassified_count`；旧字段可兼容投影，但不得继续按名称查询事实数据。
- 报告生成和 `/analysis/llm` 使用同一聚合服务，提供一级指标和必要二级证据。
- **报告中的数值由服务端写入，模型不输出计数**：提示词删除 `top_error_knowledge_points` 等计数字段的输出要求，模型只生成叙述、薄弱点理由和建议（可引用模块 ID/名称）。服务端在模型返回后把模块指标写入 `content.metrics`（与现有覆盖 `overview` 的做法一致），前端报告页的数值只读 `content.metrics`。
- 新报告 content 保存 `schema_version: 2`、taxonomy_version、统计口径（含时间窗口口径）、模块 ID 和名称快照；无版本号报告按 legacy 展示“旧版分类口径；知识点排行未按新口径复核”。不能笼统宣称所有历史数值均由模型生成，因为 overview 已由服务端覆盖；不自动重写或重新调用模型。
- 图谱：当前分析页未消费 `knowledge_graph`，本期返回一级、二级节点和父子边的最小结构，不建设图谱页面；不以空边掩盖已经存在的父子关系。

## 8. 缓存、历史产物与性能

- 版本号分工：
  - `data_revision`（已有）：任何业务写入后递增，用于服务端统计缓存失效，保持现有中间件逻辑；
  - `taxonomy_version`（新增，存 `runtime_config`）：仅目录结构/名称变更及迁移成功后递增，且与目录写入**在同一 batch 内**递增（现有中间件的 `invalidate` 在响应后单独执行，不是原子的，不能依赖它）；用于前端目录/树/颜色缓存失效和报告快照记录。
- 前端目录、树、颜色、统计缓存共同失效；修改后本页面立即可见，其他已打开页面在重新获取/聚焦刷新后获取新版本，不承诺实时推送。
- PDF 指纹加入模板版本、排序稳定的二级 ID/路径/主考点及原打印内容；再次请求时按新指纹生成，已下载 PDF 不回写，不批量生成历史 PDF。
- 报告是快照，不按当前目录悄悄替换名称或数值。
- 题目列表批量装配知识点，避免每题查询；统计使用 D1 SQL 聚合，先去重题目-模块再 JOIN 作答。
- 免费额度约束：实施前核对当前 Workers Free 下每次调用的 D1 查询次数上限和单条 SQL 绑定参数上限（100）。校验、装配、回填一律使用 `json_each` 集合查询；`summary()` 现有按学科循环查询不得再叠加按模块循环。
- 不按题重复调用模型，不为分类迁移生成报告或 PDF，不升级 Workers Paid。
- 用代表性全量与分页查询记录 SQL 次数、rows_read、耗时，核对执行计划和索引；有新增代码后再确定性能基线，不能凭空承诺固定毫秒数。

## 9. 历史数据迁移

### 9.1 审核产物

新增默认只读的预检脚本，输出到被忽略的 `tmp/` 或 `backups/`：

- 当前 D1 schema、有效题目与目录数量、按学科年级学期分布。
- 原知识点 ID/名称到新二级的映射、证据、来源和审核状态。
- 重复、跨学科、未知文本、过宽标签、空值、多考点及主考点待定列表。
- 受影响题目数、旧错误类型关联迁移结果、前后预期统计对照。

公共种子目录可以进仓库；含学生题目、答案、私有映射证据、备份和密钥不得提交。

### 9.2 映射原则

1. 明确且唯一的旧标签可确定性映射到二级；尽可能保留合适的旧目录 ID。
2. “立体几何”“词汇与语法”等宽标签需要读题细分，不能仅映射到任意一个二级。
3. “绝对值与分数运算”等复合名称允许拆成多个二级，但主考点需有审核结论。
4. 无法确认保留未分类和原标签证据，进入待处理列表，不影响题目可读可练。
5. 未完全解决的旧目录行（`level IS NULL`）不参与新树和新统计；确认无人引用且迁移证据已保存后才软删除，不硬删。

### 9.3 执行与幂等

- schema 迁移与数据回填分开；使用稳定 code 和题目-知识点唯一键幂等 upsert。回填数据以 `json_each` 传入，不逐题拼 SQL。
- 每批在 D1 batch 原子写入，批次首条用 `write_guard` 校验预期旧值/knowledge_revision；保存已完成批次，冲突批次停止，不覆盖更新。
- 应用迁移前记录 D1 Time Travel 书签（bookmark）并导出当前 D1 完整 SQL，记录文件校验值和目录版本。业务及 Agent 写入必须在最终快照和回填期间由维护开关暂停；切换后核对通过再恢复。
- 迁移脚本不得重放旧 PostgreSQL/SQLite 快照，不通过 MySQL MCP 或旧 ORM 写生产；迁移脚本通过 wrangler 直接执行 D1 语句，不经过业务 API，因此不受维护开关影响。
- 数据回填只改分类相关字段与必要版本号；题干、答案、解析、公式反斜杠、图片、作答记录和原年级学期逐项核对不变。

## 11. 验收矩阵

项目没有现成测试套件；本次关系和聚合改造需要增加针对核心不变量的自动化验证脚本，并结合实际页面验证。不得只做构建或把实现逐行复述当测试。

| 场景 | 必须满足 |
| --- | --- |
| 目录约束 | 拒绝三级、跨学科、无效父级、同级重名（含大小写/全半角差异）；拒绝删除有引用节点；已删题目的关联不阻止删除二级 |
| 间接约束 | 题目改学科但未提交新关联被拒绝；有知识点/题目的学科不能删除；一级不能挂错误类型 |
| 多考点 | 同一级两个二级只算一道；跨一级覆盖两个模块，主考点占比只算一次 |
| 作答聚合 | 同一次作答在同一级只计一次；两次有效作答计两次；零作答 accuracy=null |
| 两套正确率 | 同一数据下“模块练习正确率”与“累计批改正确率”各自可按定义复算，界面名称正确 |
| 软删除 | 删除题、关联、练习或分类后相关指标正确；不得遗留隐式无效父子关系 |
| 筛选分页 | 一级含全部子级；二级精准；总数及分页无重复；关键词支持两级名称 |
| 写入入口 | 上传、错题编辑、批改编辑、单题 API、Agent 批量 API 全覆盖 |
| 原子并发 | 注入失败不产生半条分类；两个修改基于同版本时仅一个成功，另一个 409；主考点校验失败整批回滚；触发器错误返回明确 409/422 而非 500 |
| 兼容参数 | 字段缺省保留、空数组清空、冲突字段拒绝、旧名称歧义拒绝；旧客户端回传主考点名或空字符串时多考点关联不丢失 |
| 批量入库 | 单题知识点无效只进入该题 errors，其余题目正常入库 |
| 旧数据 | 空标签、宽标签、复合标签不强猜；未分类清单可回查 |
| 报告与模型 | 新报告一级、携带版本；报告数值与聚合服务一致且不来自模型输出；旧报告可读并标注旧口径 |
| PDF | 标签变化导致新指纹；内容不变重复请求复用；公式渲染保持正确 |
| 缓存 | 更新目录或关联后目录树、颜色、题目及统计不残留旧值 |
| 维护开关 | 开启时浏览器与 Bearer 写入均返回 503；纯只读 GET、健康检查、登录正常；音频缓存未命中不得产生写入；在途写入门禁与排空通过；关闭后恢复 |
| 非错题业务 | 单词/阅读练习不被计入错题模块正确率；独立功能仍可使用 |
| 数据完整性 | 迁移前后有效题目及原文哈希一致，所有有效关联符合约束；一致性校验脚本零违规 |
| 生成脚本 | 运行已停用的生成脚本不会改写 `cloudflare/src` |

先用隔离 D1 数据及合成题执行写入验证，生产验证以只读回读为主。若必须做正式写入冒烟，使用明确临时记录并软删除，核对其不污染统计与奖励。

## 12. 发布与恢复

不采用长期维护的双模 Worker。新 Worker 只实现结构模式，但不能由“追加 schema”推断旧 Worker 一定兼容：触发器可能阻止旧 `kp_error_type` 写入，唯一索引可能受旧重复数据影响，旧目录还会产生 level=NULL 行。因此分类 schema 与触发器统一放到停写并排空在途请求之后应用；此前只发布维护控制小版本。

### 12.1 维护开关

新增集中写入维护开关，存于 D1 `runtime_config`（如 `write_maintenance`），无需重新部署即可切换：

- 开启时，`auth.py` guard 在认证通过后、业务处理前，对所有非 GET/HEAD/OPTIONS 请求返回 503“系统维护中，请稍后再试”，**包括 Bearer ACCESS_TOKEN（Agent）请求**；
- `/health`、`/login`、`/api/auth/verify-password` 及所有只读请求不受影响；
- 写请求必须独立读取维护状态，不能依赖只对特定统计 GET 生效的 `cache.lookup`。统计 GET 可在需要时合并查询版本；不要求全部 GET 额外读取维护开关。检查失败时拒绝业务写入，不能默认放行；
- 不修改生产 `MIGRATION_READY`（保持 true），它的语义保留为历史切换保护。

入口开关只能挡住新请求，不能撤销已进入的写请求或等待模型/渲染器的长请求。维护控制小版本须提供事务内写入门禁：业务 D1 写批次在同一事务断言维护状态仍允许写入；现有散落单条 D1 写入也需保护。数据库层写门禁可作为等效实现，必须覆盖 Worker 请求之外的既有后台写入。登录例外只允许会话签发，不豁免业务写入。

迁移使用独立受控通道：维护期间只允许经审核的 Wrangler 迁移执行，不新增可供 Bearer 绕过的参数或公共接口。若采用数据库级门禁，需演练维护专用迁移解锁/复锁步骤，期间保证业务请求已停止且排空。R2、音频缓存等副作用另行排空；`GET /api/words/{word_id}/audio` 可能回源写缓存，维护时仅允许命中缓存返回，缺失时返回 503，不视为纯只读接口。发布 A 必须覆盖此项。

开启维护后，等待并核对所有在途业务写入及外部生成任务结束或被事务门禁拒绝，确认 D1/R2 写入稳定后再记录最终书签并备份；不能只等待一个任意固定秒数。若无法证明排空或门禁覆盖，停止迁移。

### 12.2 发布步骤

1. 实施从最新 main 创建独立 `codex/` 分支，保留工作区其他修改，只提交本次相关文件。
2. 完成 schema 迁移、公共服务、所有消费者、回填工具、一致性校验脚本及验证；在隔离 D1 完成迁移演练和备份恢复演练（含确认 SQL 导出包含触发器与部分索引、Time Travel 恢复可用）。
3. **发布 A**：仅包含维护开关的 Worker 小版本（不含分类改造），在生产验证开关开/关行为。
4. 发布 B 的完整代码先在隔离环境通过全部检查与 `python backend/scripts/prepare_cloudflare_frontend.py` 构建，再合并 main、推送远端，固定待发布 commit 与构建产物；不得先部署 Worker 再补做前端构建。发布 A 同样先验证、合并、推送再部署。
5. 开启维护开关并按 12.1 排空；记录 Time Travel 书签并导出 schema 改动前的最终 D1 备份。应用追加 schema/触发器，执行已审核回填；运行一致性校验及聚合核对，写入 taxonomy_version。维护期间旧 Worker 不得继续目录编辑。
6. **发布 B**：部署新 Worker（同时返回新字段与兼容投影），随后部署第 4 步已验证的 Pages 产物。打印模板改变时部署内部 PDF Worker。全程维持停写，不开放旧页面对新 schema 的过渡写入。
7. 保持维护开启，先做正式只读验证及写入应返回 503 的验证；两级写入、练习及 PDF 生成已在隔离环境完成。正式只读验证通过后关闭维护，执行最小真实写入冒烟并清理临时记录；失败立即重新停写，按已有新增写入的恢复规则处理。记录 commit、迁移批次、Time Travel 书签、备份校验、部署 ID 和验证结果。维护期间不能既要求所有写入 503 又要求通过正常 API 写入成功。
8. Cloudflare 部署命令、密钥位置沿用 `docs/cloudflare-migration-status.md`，不在本文件复制凭证，不开放旧数据库写入。

兼容窗口：已打开的旧页面和未更新的 Agent 可能继续提交旧文本，按 4.3 规则处理——回传当前主考点名或空字符串视为未修改，精准名称只能映射唯一二级；未知/歧义请求返回可解释错误并提示刷新。不能允许旧客户端持续写无结构文本，也不能让旧客户端的回传清掉多考点。

### 12.3 恢复策略

- schema 采用追加方式，故障优先回滚 Worker/Pages 到发布 A 版本并保持维护开关开启；新表与新列保留，只提供经过验证的旧版只读访问。新约束可能不兼容旧写入，禁止直接恢复旧版写能力。
- 回填阶段出错且尚无新的业务写入时，可用 Time Travel 恢复到步骤 5 记录的书签；SQL 导出作为第二重保险。
- 发布 B 后已有新增写入时，禁止直接恢复到迁移前书签或导入迁移前备份；分类纠错根据私有迁移日志做受控补偿，全部软删除/恢复，不全库覆盖。
- 回滚到只懂文本的旧版本会丢失多标签语义，不作为无损回滚。

## 14. Codex 二次核对与修订（2026-11-10）

已对照 review 工作区与实际 `auth.py`、Pages 网关、`questions.py`、`practices.py`、缓存及生成脚本核对。Claude Review 的原子写入、报告指标服务端化、生成脚本覆盖风险、目录路由拆分、缓存更新和旧客户端多考点保护建议予以采纳。以下为进一步修正，不等于实现已验证：

| 问题 | 最终处理 |
| --- | --- |
| 应用层先查引用再写入仍有竞态 | 目录和学科管理的引用约束必须在数据库事务内断言；恢复记录也验证 |
| 多种 guard 失败均映射成版本冲突 | 稳定错误分类；守卫行缺失必须失败关闭；不将结构错误误报 409 版本冲突 |
| 题目换学科与即时触发器互相冲突 | 同批次先取消旧关联，再改学科和新增关联，末尾校验 |
| legacy 原文只有私有日志，API 无法日常回查 | 新增只读 legacy_knowledge_point 列；兼容投影与原标签分开 |

| 维护开关读取复用统计缓存不可覆盖写请求 | 写请求独立检查；读取失败停写，Bearer 无豁免 |
